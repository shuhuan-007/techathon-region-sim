## 二、项目一句话

**玩家经营一个区域**：摆地块、招人口、产商品、卖到全国市场、喂饱居民。

**核心循环**：

```
行动阶段（提交计划）→ 季度结算 → 月报 → 下一季
```

**三条铁律**：

1. **程序决定事实，AI 只负责解释**（AI 不得改规则、造补贴、改价格、定处罚）
2. **前端只显示、零计算**（所有数字由引擎算好）
3. **单人开发，多人结构**（第一期只做单人，但代码按多人写）

## 四、核心架构

```
web/      前端（零计算）
   ↕ HTTP
server/   只转发，不放规则
   ↕ 函数调用
engine/   ★ 全部业务逻辑，纯函数、确定性
   ↕ 读
config/   config.json
   ↕
storage/  第一期 JSON 文件，接口可替换
```

**依赖单向**：`web → server → engine → config`。

**engine 绝不 import server** —— 这样引擎能脱离 Web 单独跑测试。

### 两个入口

```python
advance(state, plans) -> GameState    # 真结算，唯一能改状态的地方
preview(state, plans) -> Report       # 试算，不改状态（AI 和 UI 都用）
```

> ⚠️ **`preview` 必须和 `advance` 共用同一份实现**，否则 AI 报的数和真实结算不一致。

## 五、五条写法红线

**功能上只做单人，代码结构按多人写。**

| # | 红线 |
|---|---|
| 1 | 玩家身份永远用 `player_id` 索引（`state["players"]["p1"]`） |
| 2 | 共享 / 私有状态分层（共享=市场价/政策/时钟；私有=现金/地块/库存/债务） |
| 3 | 收齐所有计划再结算：`advance(plans: Dict[player_id, Plan])` |
| 4 | 分配规则做成可替换策略（注入 `allocator`） |
| 5 | 服务层只转发、不放规则 |

**单→多扩展的全部代价 = 三处**：`players` 字典、`player_id` 参数、`plans` 字典。

## 六、开工顺序（测试先行）

| 步 | 做什么 |
|---|---|
| **1** | **`tests/test_m1.py`** —— 先写死验收数字 |
| 2–4 | `models.py` → `loader.py` → `production.py` + `market.py` **让 M1 通过** |
| 5–7 | 效率/人口 → 粮食链 → `pipeline.py` |
| 8–10 | 存储/会话 → 接口 → 前端对接 |

**M1 验收锚点**（★ 2026-10-16 重新生成，权威表见《规则基线》§8.1）：

| 甲区生产总支出 | 乙区生产总支出 | 增加值合计 |
|---:|---:|---:|
| **66** | **215** | **176** |

> 这三个数**不依赖价格弹性**，已按配方表 + 参考价独立复算通过（乙区 215 另有 §8.2 的「G 季度成本」独立佐证）。
> **对不上就是实现有问题**——这个反馈闭环能省掉大量调试。
>
> ⚠️ **结算价与期末现金暂不给数字**：`P_t = P0 + (B_t − X_t)/(s+d)` 依赖弹性 `Es`/`Ed`，`config.json` 里仍为 `null`（待规则同学填），程序此时**明确报错**而不是编数。
> 弹性到位后直接代入即可，**无需再改规则**：甲 `1000 − 66 + 4·P_F + 3.60`、乙 `1000 − 215 + 5·P_G + 4.50`。

**浮点用容差比对**：`abs(cost_b - 215) < 1e-6`（乙区生产总支出）、`abs(gdp_total - 176) < 1e-6`（增加值合计），别写 `==`。
