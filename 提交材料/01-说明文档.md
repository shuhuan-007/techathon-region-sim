# 一、项目简介

**区域发展模拟器 Region Sim** 是一个单人、20 季、零仓库、15 种商品弹性市场的区域经营模拟游戏。玩家从 10×10 空地 + 1200 现金起步，摆地块 → 招人口 → 产商品 → 卖市场 → 喂居民 → 抽政策 → 看月报，一季一季把一片空地经营成有产业、有人口、有财政的城区。

它的核心主张只有一句：**规则做深，算账交给机器**。市场当裁判，AI 秘书当会计；玩家保留判断，AI 永远不替玩家按下提交。

## 1.1 核心循环（玩家看到的四步）

| 步 | 玩家做什么 | 系统做什么 |
|---|---|---|
| ① 行动阶段 | 提交一份**计划**：哪些地块开工、开工率多少、建什么、买什么、买多少口粮 | 只校验、只试算，**不扣钱**（`POST /api/submit` / `/api/simulate`） |
| ② 季度结算 | 点「结算」 | 9 阶段流水线一次性跑完，**钱只在第 5 步扣一次** |
| ③ 月报 | 读新闻 + 财报 | 引擎给出全部数字；AI 只写叙事解读（`GET /api/narratives`） |
| ④ 下一季 | 看完继续 | 季度 +1，抽新政策，进入下一轮行动 |

## 1.2 九阶段季度流水线（`region-sim/engine/pipeline.py` 文件头有同一张表）

| # | 阶段 | 关键动作 |
|---:|---|---|
| 1 | 期初更新与公告 | 在建工期 −1，到期完工；本季政策生效 |
| 2 | 玩家提交计划 | 只校验，不扣钱 |
| 3 | 期初人口计算 | 效率 E → 岗位 L → 人口 N → 口粮需求 F_基准 / F_优秀 |
| 4 | 生产 | 产量 = e·u·E，投入 = input·u·E，劳动 = d·u |
| 4.5 | 买入汇总与求价 | B_t = 生产原料 + 建设物资 + 居民口粮，代入公式求 P_t |
| 5 | **一次性扣款** | 物资款（按**上季价**）+ 工资 + 经营费，本季唯一扣钱点 |
| 6 | 产品分配与工程投入 | 合同履约；本季产品投入工程 |
| 7 | 市场结算 | 产出按 P_t **全部卖出**（不用申报）；服务收入入账 |
| 7.5 | 粮食结算 | 扣 A/B/C/D → 得幸福度 H |
| 8 | 税收与报告 | 工资税 10% 记回流收入，出财报 |
| 9 | 结转 | 季度 +1，保存本季 H，写存档 |

> 「钱为什么少了」永远只有一个查得到的点——第 5 步。这条设计直接决定了月报可对账、AI 试算可信。

## 1.3 核心创新：程序决定事实，AI 只负责解释

AI 秘书有四件事，和一件**绝不做**的事：

| 能力 | 玩家问法 | 实现 | 边界 |
|---|---|---|---|
| 问 | 「这条规则什么意思？」 | `region-sim/ai/rules_digest.py` + `server/ai_host.py::advise` | 答案必须落在规则原文片段上（`_ensure_rule_answer` 兜底） |
| 算 | 「这版计划会怎样？」 | `POST /api/simulate` → `engine/pipeline.py::preview` | 只读，不改状态；与真结算同一套代码 |
| 填 | 「帮我起草这一季」 | `region-sim/ai/plan_compile.py::compile_draft` | **必须双闸全过**才回填表单 |
| 盯 | 「有没有坑？」 | `server/ai_host.py` 拼装 `ai/strategy.py` 的现金/市场/服务提示 | 只提示，不提交 |

**双闸的顺序是硬编码的**（`ai/plan_compile.py::_check`）：

1. 先 `engine.validate.validate_plan`（合法：不违反规则）；
2. 过了才 `engine.pipeline.preview`（试算：资金/结算不炸）；
3. 两条都过 → 返回 `plan`；任一不过 → `plan=None` + `issues`，**绝不把坏计划交给前端**。

**AI 无 commit** 不是靠提示词，而是靠代码边界：`region-sim/ai/tools.py::assert_import_boundary()` 在工具调用时自检两类越界——

- 模块级：`ai/` 加载**之后**新出现的 `storage` / `server.*` 等写入口直接抛 `AisImportBoundaryError`；
- 属性级：`engine.pipeline.advance` 这个**函数对象**不允许被任何 `ai.*` 模块持有（用 `is` 比身份，改名/别名都绕不过）。

结算入口只有 `POST /api/end_quarter`（人工点击）这一条路，AI 的调用链里没有它。

## 1.5 经济系统的三条「硬」约束

1. **弹性市场**：`P_t = P0 + (B_t − X_t) / (s + d)`，`s = Es·Q0/P0`、`d = |Ed|·Q0/P0`，触底按 `P_min = 0.1·P0` 全量收购（`engine/market.py`）。G 商品实测参数：P0=56、Q0=300、Es=1.0、Ed=−0.8 → `s+d = 9.642857`。
2. **零仓库**：产多少卖多少，卖不掉就是价格问题；买多了口粮没有仓库可放，结算第 7.5 步直接丢弃（所以 AI 会主动把口粮压到「优秀档吃不完」的上限）。
3. **产出即供给**：玩家产量直接进 B_t/X_t 参与求价，没有「挂单」这种操作。

## 1.6 一季的账怎么走（用 M1 甲区举例）

| 步骤 | 数 | 说明 |
|---|---|---|
| 产出 | F × 4 | 资源 L1，u=1、E=1 |
| 生产总支出 | 66 | 原料 0 + 工资 36 + 经营费 30 |
| 求价 | P_F = 17.76 | `18 + (0 − 4)/16.666667` |
| 销售收入 | 71.04 | 4 × 17.76，产出全部卖出 |
| 其他收入/支出 | +3.60 / 0 | 工资税回流 − 工资税支出 |
| 期末现金 | 1008.64 | 1000 − 66 + 71.04 + 3.60 |

> 这张表的每一格都有测试钉死（`tests/test_m1.py`）；玩家在界面上看到的「本季预览」与它逐位相同，因为预览和结算跑的是同一个 `pipeline._run`。

## 2.2 工程纪律（团队自定的三条）

1. **公式在代码、数值在配置**：任何数字都不许写进引擎字面量，一律进 `config/config.json`；缺字段就报错，不糊默认值（`engine/loader.py::ConfigError`）。
2. **文档先于实现、实现回写文档**：规则争议先改《规则基线》，再改代码，再补测试；文档里保留「旧值→新值」的溯源句（如 §8.1 的第八轮重算说明）。
3. **不写未验证的数字**：对外材料里的每个数字都能指向一个测试或一份文档；对不上就标注，不猜。

| 承诺 | 怎么保证 | 证据 |
|---|---|---|
| **钱只扣一次** | 扣款只在流水线第 5 步；提交阶段只校验 | `engine/pipeline.py` 文件头；`tests/test_pipeline.py` |
| **预览 = 结算，一分不差** | 预览与真结算共用 `_run`，`preview` 深拷贝状态后跑同一函数 | `tests/test_pipeline.py::test_preview_equals_advance`、`tests/test_report.py`（「界面上显示的本季预览，必须与真结算一分不差」） |
| **AI 无 commit** | 起草只产出 `Plan` 数据；`assert_import_boundary()` 双黑名单 | `ai/tools.py`、`ai/plan_compile.py` |

## 3.6 前端如何做到「零计算」

| 模块 | 职责 | 不做什么 |
|---|---|---|
| `web/js/api.js` | 封装 18 个端点，统一错误与 loading | 不拼业务数字 |
| `web/js/state.js` | 保存服务端最近一次返回的 state/report | 不推导、不缓存派生值 |
| `web/js/map.js` | 渲染 10×10 地块、悬停信息、资产键挂载 | 不算加成、不算价格 |
| `web/js/panel.js` | 计划表单（开工率、建造、采购、口粮） | 不做合法性判断（交给 `/api/validate`） |
| `web/js/main.js` | 装配、阶段切换、提交与结算按钮 | 不发给 AI 任何提交指令 |
| `web/js/finale.js` | 第 20 季终局界面 | 不重算 GDP |

> 数字只有一个来源：`/api/state`、`/api/report`、`/api/simulate`。前端多算一次，就多一个和引擎对不上的机会——我们选择不算。

## 3.7 存档与数据落盘

- 存储为**本地 JSON 原子写**：临时文件（同目录）→ `os.fsync` → `os.replace`，断电不会留半截档（`region-sim/storage/json_file.py`，模块头有完整理由）。
- 接口抽象在 `storage/base.py`，内存实现 `storage/memory.py` 供测试用；游戏档落 `region-sim/saves/`。
- 季末自动快照在 `server/session.py`（`end_quarter` 锁内全量快照）+ `server/slots.py`（slot 命名/校验）。

## 5.3 术语表（读财报时会遇到）

| 术语 | 含义 | 出处 |
|---|---|---|
| `B_t` / `X_t` | 本季总买入量 / 总卖出量（含居民口粮与建设物资） | `engine/market.py` |
