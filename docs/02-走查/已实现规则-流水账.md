② 市场（共享，所有玩家面对同一套）
   每商品一条供需曲线参数：P0、Q0、Es、Ed、P_min

              I 外部科研每季固定收购 15
              H+ 外部基建每季固定收购 10

③ 玩家（私有，按 player_id 索引）
   cash = 初始现金（正式值未定；测试用 1000）
   plots = {每块地: 类型 / 等级 / 状态 / 磨合计数 / 开工比例}
   inventory = {}                      计划内待用，不是自由仓库
   debts = []

④ 效率参数（来自 config，非玩家状态）
   关联表：农业←农业,资源  资源←资源,工业  工业←工业,资源
           服务←服务,农业,工业  研究←工业,高技术
   每条地块记录：c（经营费）d（劳动）e（产量）商品投入
   工资表：农业8 资源12 基础工业G15 机械H/H+20 高技术I/研究28 本地服务16

⑤ 开局：玩家自己摆地（✅ 新增机制）
   地图开局是空地，没有"零级地块"这个概念
   玩家自主决定：建哪些类型的地、每种建几块、放在哪
   建造成本享受【分类减免名额】：
       每种类型各有自己的减免名额
       {农业: n_农, 资源: n_资, 工业: n_工, 服务: n_服}
       名额内的"新建一级"打折；名额用完按原价

   ⚠️ 名额数与折扣幅度【待定】（用户例：农业2 工业2 服务1）

## 第 2 步 · 算效率 E（每块开工地块各算一个）

**服务地块走独立分支，其他地块走通用分支。**

### 通用分支（农业 / 资源 / 工业 / 研究）

```
E = E_邻接 × E_幸福 × E_磨合 × (1 + 研究加成)
```

| 分量 | 算法 |
|---|---|
| `E_邻接` | 数八邻格中**落在关联表里**的邻居个数 n<br>`E_邻接 = 1 + min(0.05 × n, 0.40)` |
| `E_幸福` | 用**上一季**的 H：<br>H < 0.6 → 0.90<br>H ≥ 0.6 → `0.90 + (H − 0.6) × 0.5` |
| `E_磨合` | 新建/升级后：第 1 季 0.5、第 2 季 0.75、第 3 季起 1.0 |
| 研究加成 | 每块正常运行的研究地块 +1%，同一玩家上限 +3%；**不对研究地块自身加成** |

**排除项**：升级中、在建、未运行的地块**不提供**邻接加成。

**例**：农业地块周围 1 农 + 2 资源 → n=3 → `E_邻接 = 1.15`

### 服务分支

```
E_邻接 = 1 + 0.10 × (所有相邻地块数)     ← 不看关联表，任何邻居都算
```
其余分量（幸福度/磨合/研究）建议沿用，**待确认**。

## 第 3 步 · 算岗位数与人口

```
L = Σ(所有开工地块的 d × u)          岗位数
N = round(L × 2)                     人口（r = 2）
```

**注意**：`d × u`，**不乘 E**。效率不放大劳动。

| 岗位 L | 3 | 5 | 11 | 25 | 50 |
|---|---:|---:|---:|---:|---:|
| 人口 N | 6 | 10 | 22 | 50 | 100 |

**r = 2 已定案**（先符合客观现实，数值调节另议）。

## 第 4 步 · 算粮食需求

```
ḡ = 所有开工地块的平均等级        ← 含农业/资源/工业/服务/研究；不含 0 级空地、在建
m = 1 + 0.15 × (ḡ − 1)          等级乘数

F_基准 = (N / 5) × m
F_优秀 = 1.5 × F_基准
```

| ḡ | 1.0 | 1.5 | 2.0 | 2.5 | 3.0 |
|---|---:|---:|---:|---:|---:|
| m | 1.000 | 1.075 | 1.150 | 1.225 | 1.300 |

**两档要的东西不一样：**

| 档位 | 需要 | 说明 |
|---|---|---|
| **基准** | **A、B** | 口粮。**必须都有，且可互相替换** |
| **优秀** | **A、B、C、D** | 生活品质。**四样全要** |

**基准档判定算法**：

```
R = 0.6 × F_基准                                    A、B 合计口粮需求
S = min(A投放, 0.4×F_基准) + min(B投放, 0.2×F_基准)

必须：A投放 = 0 或 B投放 = 0  →  基准档不成立
可替换：各自配额上限内互补，S ≥ R 即达标
```

**例**（F_基准 = 2.0）：

| 投放 | 结果 |
|---|---|
| A0.8 / B0.4 | ✅ 达标 |
| A1.2 / B0 | ✅ 达标（A 补了 B） |
| A0 / B1.2 | ❌ 不达标（B 到 0.4 封顶，补不满） |
| 完全不投 | ❌ H = 0 |

> ⚠️ 这里算出的 `F_基准 / F_优秀` 是**结算时的判定标准**，不是期初的自动扣款额。见第 5 步。

## 第 5 步 · 期初支配资金

```
按【上期价格】买入本季生产所需原料
扣除工资和经营费用
【可选】按上期价买入粮食，囤着备结算用
```

**时序铁律**：本季生产出来的东西，**不能倒填本季已经开始的消费**。

### 粮食是玩家的主动选择（✅ 关键）

> **粮食扣减不在期初，在结算时。**
> 期初是玩家**支配资金**的阶段——他可以自己决定：这一季要不要花钱买粮食、买多少、要不要冲优秀档。
> 系统**不预先代扣**，也不强制玩家满足粮食需求。**买不买、买多少，是玩家的经营决策。**

这意味着粮食需求是一个**取舍**：钱可以拿去扩产，也可以拿去让居民吃好。吃得好 → 下季效率高；吃得差 → 下季效率被压。**这个取舍本身就是玩法。**

## 第 6 步 · 生产

```
产量     = e × u × E
商品投入 = 基础投入 × u × E
劳动需求 = d × u                 ← 不乘 E
经营费   = 0                     , u = 0
         = 0.7c + 0.3c × u × E  , u > 0
```

**总成本** = `Σ(原料数量 × 采购价) + 经营费 + 劳动 × 工资`

⚠️ 材料费和经营费 c 是两笔，**不能把材料塞进 c 又扣一次采购款**。

**服务地块**：0 → 0，不产出商品、也没有收入，**纯烧钱**（换邻接效率加成）。

---

## 第 7 步 · 算幸福度 H

设 `F` = 实际达成的等效篮位数：

```
H = 0.6 × (F / F_基准)                              , F < F_基准
H = 0.6 + 0.4 × (F − F_基准) / (F_优秀 − F_基准)    , F_基准 ≤ F < F_优秀
H = 1.0                                             , F ≥ F_优秀
```

| F / F_基准 | 0 | 0.5 | 0.8 | **1.0** | 1.2 | **1.5** |
|---|---:|---:|---:|---:|---:|---:|
| **H** | 0.00 | 0.30 | 0.48 | **0.60** | 0.76 | **1.00** |
| **E_幸福**（下季用） | 0.90 | 0.90 | 0.90 | **0.90** | 0.98 | **1.10** |

**这是惩罚回路**：粮食不够 → H 降 → **下季**效率降。

**第一季度没有"上季 H"**：`H₀ = 0.6`（开局 `E_幸福 = 0.90`，中性起点）。**已确认。**

## 第 8 步 · 建设与升级（如有）

机械**只在新建/升级时一次性消耗**，日常维护走经营费 c。

| 工程 | 现金费 | 物资 | 工期 |
|---|---:|---|---:|
| 新建一级农业 | 80 | H-A×1 | 1季 |
| 农业 1→2 | 80 | H-A×1 | 2季 |
| 农业 2→3 | 100 | H-A+×1 | 3季 |
| 新建一级资源 | 100 | H-F×1 | 1季 |
| 资源 1→2 | 120 | H-F×2 | 2季 |
| 资源 2→3 | 160 | H-F+×1 | 3季 |
| 新建一级工业 G | 180 | H-G×2 | 2季 |
| G→二级机械 H | 240 | H-G×3 | 2季 |
| G→二级研究 | 300 | H-G×3 | **6季** |
| 二级研究→三级 I | 500 | H-G×5 | **8季** |

## 第 9 步 · 市场结算

### 全国商品

```
S_外(P) = max(0, Q0 + s(P − P0))
D_外(P) = max(0, Q0 − d(P − P0))
s = Es × Q0 / P0        d = |Ed| × Q0 / P0

求价：S_外 + X_t = D_外 + B_t
P_t = P0 + (B_t − X_t) / (s + d)
```

`B_t` = 本季从公开市场买入量；`X_t` = 扣除合同交付与自用后准备卖出的量。

**期初按上期价买，季末按本期价卖。**

**价格下限** `P_min = 0.1 × P0`。到下限仍过剩 → **按可实现需求量分配成交，不保证全量收购**；未售商品清理，不产生收入。

⚠️ 不能只把负价格截成 0 然后让全部产量成交。

### 服务

不走全国市场、不出口、**不代购 A/B/C/D、也没有收入**。

**服务是纯基础设施**：烧钱，换邻接 +10% 效率。收益体现在别的地块的产量上（第 2 步）。

## 第 9.5 步 · 粮食结算（✅ 关键步骤）

**结算时才扣粮食。** 顺序：先市场卖出 → 拿到钱和剩余货物 → **然后扣粮食**。

```
① 数出玩家手上可用于吃的 A / B / C / D 数量
      （= 本季留存 + 自产未售 + 本季买入的粮食）
② 判定基准档：A、B 都必须有 → S = min(A, 0.4×F_基准) + min(B, 0.2×F_基准)
      S ≥ 0.6×F_基准  →  基准达标
③ 判定优秀档：A/B/C/D 四样配额齐全 → 优秀达标
④ 扣减：有多少扣多少，不足扣光，不欠账
⑤ 算出实际达成 F → 得 H（第 7 步公式）
```

**"扣光、不欠账"的确切含义**：

| 情况 | 扣减 | H |
|---|---|---|
| 达到优秀 | 扣满 A/B/C/D 配额 | 1.00 |
| 只达到基准 | 扣 A、B（按配额），C/D 不扣 | 0.60 |
| 部分达到 | **扣光手上所有能吃的** | `0.6 × 实际/F_基准` |
| 完全不投 | 扣 0 | 0.00 |

> **注意**：玩家期初可以选择不买粮食。结算时若手上没有，就扣不到东西，H 直接掉——**后果由下季效率承担**。

## 第 10 步 · 税收 / 违约 / 报告

```
工资税 = W × 10%
   工资支出记【税前总额】
   工资税记【回流收入】
   净支出 = 税后工资
```

**GDP（增加值）** = `有效产出价值 − 实际消耗的中间投入价值`

- 用**固定统计价**（参考价），不随季度成交价变
- 工资**不**作中间投入再扣
- 原料**要**扣；经营费 c（维护/能源/外购服务）**要**扣
- **粮食扣减也算中间投入，要扣**（居民消费实际消耗了商品）
- 贷款、拨款、税款**不计入**
- 建设与研发成果**单独报告**，不硬塞进 GDP

**合同**：本季生产后的交货，**不能支持接收方本季已完成的生产**。收到的货只能用于未执行的本季工程，或进入本季销售；**不自动留到下季**。

**违约**：程序记录未履约 → 受损方可接受/协商/上报 → 上报确认后形成赔偿或待清偿义务 → 进政策信用状态 → 严重违约可能失去新补贴资格。**已承诺拨款不撤回。**

```
保存：现金 / 设施 / 工程进度 / 债务 / 历史价格 / 本季 H
不保存：普通待售库存
quarter += 1
```

## 一图流

```
Plan 提交（含：要不要买粮食、买多少）
  ↓
算 E（邻接 × 幸福 × 磨合 × 研究）        ← 服务走独立分支
  ↓
L = Σ(d×u)  →  N = L×2  →  ḡ  →  m
  ↓
F_基准 = (N/5)×m    F_优秀 = 1.5×F_基准
  ↓
期初：按上期价采购原料 + 扣工资经营费
      （粮食可选，玩家自己决定买不买）
  ↓
生产：产量 = e·u·E      成本 = 原料 + 经营费 + 工资
  ↓
建设 / 升级（一次性扣机械，工期推进）
  ↓
市场结算：全国求价 + 服务收入
  ↓
【粮食结算】扣 A/B/C/D（有多少扣多少）
  ↓
H = 由实际达成插值   →   下季 E_幸福
  ↓
工资税 + 违约 + 财报 + GDP
  ↓
结转 → 下一季
```

### ❌ 4 项硬阻塞 —— 这是什么意思

**硬阻塞 = 不先定下来，代码就没法开始写**（不是"缺个数值"，是"缺个形状"）。

数值缺了可以先用占位符跑起来，以后再调；但**下面这四样决定代码长什么样**，事后改要动全身：

| # | 缺什么 | 为什么卡 |
|---|---|---|
| 1 | **`config.json` schema** | 配方/价格/工资/建设/政策怎么分节、字段叫什么。第三位同学要按这个填数据，程序要按这个读。**它不定，数据同学没法开始，程序也没法读** |
| 2 | **地块 ID 与邻接表示法** | 地图怎么存？`(x,y)` 还是 `r1c1`？八邻格怎么枚举？**它决定"邻接加成"怎么算** —— 而邻接是本项目第一条效率规则 |
| 3 | **`Plan` 结构** | 玩家一季度的操作（哪块地开工、买什么、建什么）打包成什么形状。**它决定前端要传什么给后端** |
| 4 | **存档格式** | 第 11 步"结转"要存什么、怎么序列化。**它决定状态对象能不能直接落盘** |

> **共同点**：这四样都是**接口形状**，不是数值。
> 数值设计可以先残缺（比如服务费公式没定，先留个 `pass`），但**接口形状不定，两个人写的代码接不上**。
> 所以第 0 步就是把这四个形状锁死。

### 服务收入怎么算（A1/A2 我的建议）

既然确认了**服务不代购 A/B/C/D**，服务就彻底简化了：**0 → 0，纯资金流**。

```
服务地块支出 = 经营费 (0.7c + 0.3c×u×E) + 工资 d×u×16
服务地块收入 = 服务费
```

**服务费建议用这个形式**（简单、有饱和、不需外部预算）：

```
服务能力  Q = Σ(该区域所有服务地块: 等级基准 × u × E)
             等级基准：1级=5  2级=8  3级=12

服务覆盖率 = min(1, Q / (N/5))            ← N/5 是居民篮位数
服务费单价 = 基础费 × 覆盖率系数
收入       = 服务费单价 × Q_实际成交
```

**更简单的做法（推荐第一期先用）**：

```
服务收入 = 20 × min(Q, N/5)
```

含义：每份服务收 20 元，最多只能服务 `N/5` 份（居民就那么多）。**服务建多了收入不涨**——自然形成容量约束，且一个常数搞定。
