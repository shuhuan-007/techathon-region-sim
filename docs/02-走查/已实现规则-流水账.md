## 第 2 步 · 算效率 E（每块开工地块各算一个）

**服务地块走独立分支，其他地块走通用分支。**

### 通用分支（农业 / 资源 / 工业 / 研究）

```
E = E_邻接 × E_幸福 × E_磨合 × (1 + 研究加成)
```

| 分量 | 算法 |
|---|---|
| `E_邻接` | 数八邻格中**落在关联表里**的邻居个数 n<br>`E_邻接 = 1 + min(0.05 × n, 0.40)` |
| `E_幸福` | 用**上一季**的 H：<br>H < 0.6 → 0.90<br>H ≥ 0.6 → `0.90 + (H − 0.6) × 0.5` |
| `E_磨合` | 新建/升级后：第 1 季 0.5、第 2 季 0.75、第 3 季起 1.0 |
| 研究加成 | 每块正常运行的研究地块 +1%，同一玩家上限 +3%；**不对研究地块自身加成** |

**排除项**：升级中、在建、未运行的地块**不提供**邻接加成。

**例**：农业地块周围 1 农 + 2 资源 → n=3 → `E_邻接 = 1.15`

### 服务分支（✅ 2026-10-16 改定：加成率按服务自身等级）

```
E_邻接(服务) = 1 + rate(等级) × (所有相邻地块数)   ← 不看关联表，任何邻居都算
rate: 1级 = 0.05    2级 = 0.075    3级 = 0.10
```

| 服务等级 | 每邻居加成 |
|---|---:|
| 1 级 | +5% |
| 2 级 | +7.5% |
| 3 级 | +10% |

- **邻接上限**：服务**暂不封顶**（8 邻居、三级服务理论上限 +80%），与其他地块的 +40% 封顶不一致，属初始估值。
- **别人给服务的加成**仍走关联表（服务认 服务/农业/工业），每个 +5%、封顶 +40%——即"服务给出去"用等级率，"别人给服务"用关联表。
- 其余分量（幸福度/磨合/研究）建议沿用，**待确认**。

> **本轮改动说明（2026-10-16）**：此前是"任何邻居一律 +10%、不分等级"，导致三级服务与一级服务收益完全相同、升级无意义。
> 现按服务自身等级取 5% / 7.5% / 10%。率表进 `config`，不写死在代码里。
> 详见基线 §3.6。

## 第 3 步 · 算岗位数与人口

```
L = Σ(所有开工地块的 d × u)          岗位数
N = L × 2                            人口（r = 2）★ 不取整
```

**注意**：`d × u`，**不乘 E**。效率不放大劳动。

| 岗位 L | 3 | 5 | 11 | 25 | 50 |
|---|---:|---:|---:|---:|---:|
| 人口 N | 6 | 10 | 22 | 50 | 100 |

**r = 2 已定案**（先符合客观现实，数值调节另议）。

### ✅ 2026-10-16：取消 `round`，`L` 与 `N` 都保留小数

原写法 `N = round(L × 2)` 作废，改为 **`N = L × 2`，不做任何取整**。

**为什么 `L` 本身就是小数**——因为 `L` 不是"几块地"，而是"这季实际雇了多少劳动量"，两个来源都会让它带小数：

| 来源 | 例子 |
|---|---|
| **`u` 是 0–1 的比例** | 一块 1 级农业 `d=2`，半开工 `u=0.5` → `L = 2 × 0.5 = 1` |
| **`d` 本身就是小数** | 一块 3 级农业 `d=1.5`，满负荷 `u=1` → `L = 1.5` |

配方里三级地块的 `d` 大量是 `1.5 / 2.5`，所以**即使全部满负荷开工，`L` 也天然带小数**。

> ⚠️ **引擎一律存小数**（否则账对不上），**显示层负责取整或取一位小数**（界面上不出现"1.5 人"）。
> 这不是"人口可以是半个人"，而是 `d` 的口径是**劳动投入当量**而非人头数。

> **由此本项目计算链上不存在任何四舍五入**：`L / N / ḡ / m / F / H / E / P_t` 全部是连续量，一路小数算到底。
> 唯一涉及"取整"的地方是**显示层**——那是 UI 的事，与规则无关。
>
> ⚠️ **待调数值**：若希望 `L` 恒为整数，要改的是**配方里的 `d`**（全改整数）与 **`u` 的粒度**（只允许 0/1），**不是加一个 `round` 去掩盖它**。不改配方。详见基线 §3.3.1。

## 第 4 步 · 算粮食需求

```
ḡ = 所有开工地块的平均等级        ← 含农业/资源/工业/服务/研究；不含 0 级空地、在建
m = 1 + 0.15 × (ḡ − 1)          等级乘数

F_基准 = (N / 5) × m             ← ★ 只由【非服务地块】的岗位推出
F_优秀 = 1.5 × F_基准
```

### ✅ 2026-10-16：服务地块没有粮食需求

> **服务地块既不提供食物、也不消耗食物。** 它 0→0，纯资金流，与 A/B/C/D 完全无关。

也就是说 `F_基准 / F_优秀` 的判定与扣减，**只跟非服务地块产生的居民需求有关**：

| 服务地块贡献"要吃多少" | ❌ 不贡献 |
| 服务地块贡献"能吃什么" | ❌ 不贡献 |

**落地口径**：算 `L`（进而是 `N`、`F_基准`）时，**把服务地块的 `d` 从 `L` 里剔掉**——这是本节唯一需要按类型分支的地方。

> ⚠️ 注意与相邻两条规则的区别，别混：
> - **`ḡ`（平均等级）仍含服务地块**——因为它们也有岗位（见上方）。
> - **`L` 用于人口时的口径**与用于 `F_基准` 的口径在此分叉：服务地块的 `d` **不计入粮食需求**。
> - 服务地块自己仍然要发工资、仍烧经营费（第 6 步），只是**不吃粮**。
>
> 详见基线 §3.3.6。

| ḡ | 1.0 | 1.5 | 2.0 | 2.5 | 3.0 |
|---|---:|---:|---:|---:|---:|
| m | 1.000 | 1.075 | 1.150 | 1.225 | 1.300 |

**两档要的东西不一样：**

| 档位 | 需要 | 说明 |
|---|---|---|
| **基准** | **A、B** | 口粮。**必须都有，且可互相替换** |
| **优秀** | **A、B、C、D** | 生活品质。**四样全要** |

**基准档判定算法**：

```
R = 0.6 × F_基准                                    A、B 合计口粮需求
S = min(A投放, 0.4×F_基准) + min(B投放, 0.2×F_基准)

必须：A投放 = 0 或 B投放 = 0  →  基准档不成立
可替换：各自配额上限内互补，S ≥ R 即达标
```

**例**（F_基准 = 2.0）：

| 投放 | 结果 |
|---|---|
| A0.8 / B0.4 | ✅ 达标 |
| A1.2 / B0 | ✅ 达标（A 补了 B） |
| A0 / B1.2 | ❌ 不达标（B 到 0.4 封顶，补不满） |
| 完全不投 | ❌ H = 0 |

> ⚠️ 这里算出的 `F_基准 / F_优秀` 是**结算时的判定标准**，不是期初的自动扣款额。见第 5 步。

## 第 5 步 · 玩家阶段只提交 Plan（✅ 2026-10-16 重写）

> **本轮改动**：此前第 5 步写的是"**期初**支配资金：按上期价买原料 + 扣工资和经营费"。
> 现按裁定改为——**玩家阶段一分钱都不扣**。

### 玩家阶段（期初）：只写意愿

```
玩家在这一步【只提交 Plan】：
    哪些地块开工、开工比例 u
    申报采购：生产原料 / 建设物资 / 居民口粮
    工程指令、合同动作

❌ 不申报卖出   产出即供给（X_t = 本季产出 − 合同交付量），没有"要卖多少"这回事
❌ 不扣钱      账户余额原封不动
❌ 不锁价      不锁定任何价格
❌ 不动账户    没有"期初付款"这件事
```

| 项 | 玩家阶段（期初） | 结算时 |
|---|---|---|
| 扣款 | **❌ 不动** | ✅ 全部在此发生 |
| 价格 | 不锁 | **按上一季度结算价记账** |
| 账户 | 原封不动 | 一次性扣清 |

### 结算时：一次性扣款（唯一的扣款点）

**所有采购统统在结算时落账**——生产原料 + 建设物资 + 居民口粮，外加**工资**与**经营费**，**一笔从公用账户扣清**：

```
一次性扣款 = 物资款（生产原料 + 建设物资 + 口粮，按【上季价】记账）
           + 工资
           + 经营费
           ↓
   一笔从公用账户扣清      ← 本季度唯一扣款点
```

> ⚠️ **资金校验也放在这一步**：`物资款 + 工资 + 经营费 ≤ 现金`，超支即 Plan 无效。
> ⚠️ **注意"期初买"是口语说法**：严格说这是"**结算时按上季价买入**"——落点在**价格用的是上季那个价**，不在时点。
>
> 详见基线 §6「一次性扣款」与 §4.1「交割时序与扣款」。

**时序铁律**：本季生产出来的东西，**不能倒填本季已经开始的消费**。

### 粮食是玩家的主动选择（✅ 关键）

> **粮食扣减不在期初，在结算时。**
> 期初是玩家**支配资金**的阶段——他可以自己决定：这一季要不要花钱买粮食、买多少、要不要冲优秀档。
> 系统**不预先代扣**，也不强制玩家满足粮食需求。**买不买、买多少，是玩家的经营决策。**

这意味着粮食需求是一个**取舍**：钱可以拿去扩产，也可以拿去让居民吃好。吃得好 → 下季效率高；吃得差 → 下季效率被压。**这个取舍本身就是玩法。**

> ⚠️ **产出不能吃（✅ 2026-10-16）**：本季**种出来的** A/B/C/D 已经**全部是市场供给**，
> 不能拿来当居民口粮。**只种地、`purchases` 里不买粮 → 居民吃不到 → H = 0。**
> 口粮必须**花钱买**，这正是不买就挨饿的惩罚回路。
>
> ⚠️ **买多了要丢弃**：买的口粮超过居民实际吃的量时，**多余部分丢弃**——不产生收入、不结转到下季。
> 因为它已经不是"待售商品"，而是**买错了的东西**。
>
> 详见基线 §4.1 与 §11.1（旧"季末清仓"整节已作废）。

## 第 6 步 · 生产

```
产量     = e × u × E
商品投入 = 基础投入 × u × E
劳动需求 = d × u                 ← 不乘 E
经营费   = 0                     , u = 0
         = 0.7c + 0.3c × u × E  , u > 0
```

**总成本** = `Σ(原料数量 × 采购价) + 经营费 + 劳动 × 工资`

⚠️ 材料费和经营费 c 是两笔，**不能把材料塞进 c 又扣一次采购款**。

> ⚠️ **原料当场消耗（✅ 2026-10-16）**：生产投入（如 G 工厂的 `C×2 + D×1 + F×3`）
> **在生产时就被消耗掉**，**不会躺在库存里**——所以也不会被第 9.5 步的居民当成口粮吃掉。
> 没有仓库之后，"**什么进库存**"是一条必须显式想清楚的边界：只有**买来的口粮**进"可食用"清单。
> （这一条是真事：漏了它，G 工厂买的生产原料会被当成口粮扣掉，增加值会算错。）
>
> ⚠️ **产出当季全部成为供给**：产量算完**不做任何"要卖多少"的申报**，`X_t` = 本季产出（− 合同交付量）。
> **本季产出不能倒填本季已开始的生产**（铁律 4），也**不能拿来吃**（第 9.5 步）。

**服务地块**：0 → 0，不产出商品、也没有收入，**纯烧钱**（换邻接效率加成）。

## 第 7 步 · 算幸福度 H

设 `F` = 实际达成的等效篮位数：

```
H = 0.6 × (F / F_基准)                              , F < F_基准
H = 0.6 + 0.4 × (F − F_基准) / (F_优秀 − F_基准)    , F_基准 ≤ F < F_优秀
H = 1.0                                             , F ≥ F_优秀
```

| F / F_基准 | 0 | 0.5 | 0.8 | **1.0** | 1.2 | **1.5** |
|---|---:|---:|---:|---:|---:|---:|
| **H** | 0.00 | 0.30 | 0.48 | **0.60** | 0.76 | **1.00** |
| **E_幸福**（下季用） | 0.90 | 0.90 | 0.90 | **0.90** | 0.98 | **1.10** |

**这是惩罚回路**：粮食不够 → H 降 → **下季**效率降。

## 第 9 步 · 市场结算

### 全国商品

```
S_外(P) = max(0, Q0 + s(P − P0))
D_外(P) = max(0, Q0 − d(P − P0))
s = Es × Q0 / P0        d = |Ed| × Q0 / P0

求价：S_外 + X_t = D_外 + B_t
P_t = P0 + (B_t − X_t) / (s + d)
```

`B_t` = 本季从公开市场买入量；`X_t` = 本季产出（− 合同交付量）。

### ✅ 2026-10-16：`X_t` = 本季产出，**不申报卖出**

> **产出即供给**——生产出来多少，就当季全部成为市场供给。**没有"申报要卖多少"这一步。**
> 玩家唯一能少卖的情形是**合同交付**：货没进公开市场，就不该压价。

| 通道 | 对求价的影响 |
|---|---|
| **公开市场**（默认，全部产出） | `X_t` = 本季产出 |
| **合同交付**（保留通道，第一期不实现） | 卖方 `X_t` = 产出 − 合同交付量；买方 `B_t` = 采购量 − 合同收货量 |

> ⚠️ **卖方、买方两侧都要扣**，否则合同会凭空扰动市场：卖方的货没进公开市场**不该压价**，
> 买方的货不是从公开市场拿的**不该抬价**。
>
> ⚠️ **合同价由双方协商、低于市场价，不走 `P_t`**。
> 接口已留：`Plan.contracts` + `pipeline._contract_deliveries()`；
> **第一期该函数明确报错**（"功能未实现"）而**不是静默忽略**——忽略会让玩家以为货交出去了。

### ✅ 2026-10-16：`B_t` 明确包含三段

> **`B_t` = 生产原料 + 建设物资 + 居民口粮。三段全部计入，缺一不可。**

| 段 | 说明 |
|---|---|
| **生产原料** | 本季生产要烧的商品投入（**生产时当场消耗，不进库存**） |
| **建设物资** | 新建/升级要用的机械（H-*），**一次性买入但同样扰动市场** |
| **居民口粮** | A/B/C/D，玩家主动决定买多少（**产出不能吃，只能买**） |

**买入会把本季价格顶上去**：`B_t` 越大 → `P_t` 越高。而**你的买入价锁在上季价**——这个价差就是交割成本。

```
P_t = P0 + (B_t − X_t) / (s + d)      ← B_t 顶高本季价
   ↓
卖出按 P_t（本季价）
买入按【上季价】                       ← 两者价差 = 交割成本
```

**为什么这个闭环自洽**：买入锁在旧价、卖出随新价。买入越多 → 本季 `P_t` 越高 → 但货是在**上季价**上拿的。这天然惩罚"无脑囤货"，又给了"提前锁价"的真实市场味道。

> ⚠️ **首季没有"上季价"** → 用参考价 `P0` 兜底。
> ⚠️ 上一版这里写的"**期初按上期价买，季末按本期价卖**"是**时点上的口语说法**，已按 2026-10-16 裁定修正为：**买卖都在结算时发生，区别只在"用哪个价"**（见第 5 步）。

**价格下限** `P_min = 0.1 × P0`。到下限仍过剩 → **按可实现需求量分配成交，不保证全量收购**；未售商品清理，不产生收入。

⚠️ 不能只把负价格截成 0 然后让全部产量成交。

### 服务

不走全国市场、不出口、**不代购 A/B/C/D、也没有收入**。

**服务是纯基础设施**：烧钱，换邻接效率加成（**按服务自身等级 5% / 7.5% / 10%**，见第 2 步）。收益体现在别的地块的产量上。

## 第 9.5 步 · 粮食结算（✅ 关键步骤）

**结算时才扣粮食。** 顺序：先市场卖出 → 拿到钱 → **然后扣买来的口粮**。

```
① 数出玩家手上可用于吃的 A / B / C / D 数量
      ★ = 本季【买来的】口粮（✅ 2026-10-16：产出已全部是市场供给，不能吃）
② 判定基准档：A、B 都必须有 → S = min(A, 0.4×F_基准) + min(B, 0.2×F_基准)
      S ≥ 0.6×F_基准  →  基准达标
③ 判定优秀档：A/B/C/D 四样配额齐全 → 优秀达标
④ 扣减：有多少扣多少，不足扣光，不欠账
⑤ 算出实际达成 F → 得 H（第 7 步公式）
⑥ 剩余：买多了没吃完的口粮 → 丢弃（不产生收入、不结转）
```

> ⚠️ **第 ① 条是本轮最关键的改动（2026-10-16）**：**自产粮食不在"可吃"清单里**。
> 产出即供给，本季种出来的 A/B/C/D 已经全部进公开市场卖了；
> 居民要吃饭，**只能在 `purchases` 里买**。**只种 A 不买粮 → H = 0。**
>
> ⚠️ **第 ⑥ 条**：`④` 扣减之后剩下的口粮**丢弃**——它已经不是"待售商品"，而是买错了的东西。
> 没有仓库，所以既不能退、也不能留到下一季。（基线 §11.1）

**"扣光、不欠账"的确切含义**：

| 情况 | 扣减 | H |
|---|---|---|
| 达到优秀 | 扣满 A/B/C/D 配额 | 1.00 |
| 只达到基准 | 扣 A、B（按配额），C/D 不扣 | 0.60 |
| 部分达到 | **扣光手上所有能吃的** | `0.6 × 实际/F_基准` |
| 完全不投 | 扣 0 | 0.00 |

> **注意**：玩家在 Plan 里可以选择不买粮食。结算时若手上没有，就扣不到东西，H 直接掉——**后果由下季效率承担**。
>
> ⚠️ **与产出的关系（本轮澄清）**：旧写法"自产粮可吃"**作废**。
> 本季生产出的粮食**不能用于本季居民消费**——它已经全部是市场供给。

## 第 10 步 · 税收 / 违约 / 报告

```
工资税 = W × 10%
   工资支出记【税前总额】
   工资税记【回流收入】
   净支出 = 税后工资
```

**GDP（增加值）** = `有效产出价值 − 实际消耗的中间投入价值`

- 用**固定统计价**（参考价），不随季度成交价变
- 工资**不**作中间投入再扣
- 原料**要**扣；经营费 c（维护/能源/外购服务）**要**扣
- **粮食扣减也算中间投入，要扣**（居民消费实际消耗了商品）
- 贷款、拨款、税款**不计入**
- 建设与研发成果**单独报告**，不硬塞进 GDP

**合同**：本季生产后的交货，**不能支持接收方本季已完成的生产**。收到的货只能用于未执行的本季工程，**或进入本季销售**（没有仓库，**不自动留到下季**）。

**违约**：程序记录未履约 → 受损方可接受/协商/上报 → 上报确认后形成赔偿或待清偿义务 → 进政策信用状态 → 严重违约可能失去新补贴资格。**已承诺拨款不撤回。**

### ❌ 4 项硬阻塞 —— 这是什么意思

**硬阻塞 = 不先定下来，代码就没法开始写**（不是"缺个数值"，是"缺个形状"）。

数值缺了可以先用占位符跑起来，以后再调；但**下面这四样决定代码长什么样**，事后改要动全身：

| # | 缺什么 | 为什么卡 |
|---|---|---|
| 1 | **`config.json` schema** | 配方/价格/工资/建设/政策怎么分节、字段叫什么。第三位同学要按这个填数据，程序要按这个读。**它不定，数据同学没法开始，程序也没法读** |
| 2 | **地块 ID 与邻接表示法** | 地图怎么存？`(x,y)` 还是 `r1c1`？八邻格怎么枚举？**它决定"邻接加成"怎么算** —— 而邻接是本项目第一条效率规则 |
| 3 | **`Plan` 结构** | 玩家一季度的操作（哪块地开工、买什么、建什么）打包成什么形状。**它决定前端要传什么给后端** |
| 4 | **存档格式** | 第 11 步"结转"要存什么、怎么序列化。**它决定状态对象能不能直接落盘** |

> **共同点**：这四样都是**接口形状**，不是数值。
> 数值设计可以先残缺（比如服务费公式没定，先留个 `pass`），但**接口形状不定，两个人写的代码接不上**。
> 所以第 0 步就是把这四个形状锁死。
