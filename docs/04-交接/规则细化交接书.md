## 〇、先看这三件事

### 1. 你的交付物是什么

| 交付物 | 内容 | 优先级 |
|---|---|---|
| **`config.json`** | 全部静态数据（配方/价格/工资/建设/政策） | 🔴 最高 |
| **边界情况清单** | 每条规则的"如果……怎么办" | 🔴 高 |
| **数值校验** | 关键数字的独立复算 | 🟡 中 |

### 2. 铁律：程序决定事实，AI 只负责解释

- **程序**算：产量、成本、价格、结算、税收、处罚
- **AI** 只负责：财报解读、新闻、合同起草、政策说明
- **AI 不得**改规则、造补贴、改价格、定处罚

你写 config 时，**凡是"数值"都进 config；凡是"公式"都进代码**。不要试图用 config 表达 if-else 逻辑。

### 3. 已拍板的规则不要重新设计

下面标 ✅ 的**已经定了**，你只需要落地。标 ⚠️ 的**需要你或用户确认**。

**`P_min`** 不用手填，程序算 `0.1 × P0`。

> **第一期不实现**：提交即明确报错）。详见 §三 与基线 §4.1 / §11.1。

> ⚠️ **固定收购已全部停用（✅ 2026-10-16 定案）**：用户裁定"**暂时没有固定采购**"。

### 1.4 邻接关联表（✅ 已拍板：不只看同类型）

**这是本轮改动最大的地方**——旧规则只算同类型，现在按关联表。

```json
"adjacency_table": {
  "agriculture": ["agriculture", "resource"],
  "resource":    ["resource", "industry"],
  "industry":    ["industry", "resource"],
  "service":     ["service", "agriculture", "industry"],
  "research":    ["industry", "high_tech"]
}
```

**规则**：每个关联邻居 → `+5%`，上限 `+40%`。

```
E_邻接 = 1 + min(0.05 × 关联邻居数, 0.40)
```

> ⚠️ **服务是唯一例外**：**任何**邻居都算，不看关联表；
> 但**率按服务自身的等级取**（✅ 2026-10-16 改定）：一级 `+5%`、二级 `+7.5%`、三级 `+10%`，
> 且服务邻接**封顶 +40%**（✅ 2026-10-16 晚拍板，与其他地块一致；原"暂不封顶、8 邻居 +80%"已作废）。
> 代码里服务要单独分支；**率表进 config**（如 `efficiency.adjacency.service_rate_by_level`），不要写死。
>
> ```
> E_邻接(服务) = 1 + rate(服务等级) × (所有相邻地块数)
> rate: 1级 = 0.05   2级 = 0.075   3级 = 0.10
> ```
>
> 而**别人给服务的加成**仍走上面的关联表（服务认 服务 / 农业 / 工业），每个 +5%、封顶 +40%。
>
> ⚠️ **上限已裁定（2026-10-16 晚改定）**：**封顶 +40%**（此前"暂不封顶"作废）；见 §五-5。

## 二、规则逻辑清单（已定，供你核对边界）

### 2.1 效率 E

```
E = E_邻接 × E_幸福 × E_磨合 × (1 + 研究加成)
```

**乘法，不是加法。**

| 分量 | 公式 | 范围 |
|---|---|---|
| `E_邻接` | `1 + min(0.05 × 关联邻居数, 0.40)` | 1.00–1.40 |
| `E_幸福` | `H < 0.6 → 0.90`；否则 `0.90 + (H−0.6)×0.5` | 0.90–1.10 |
| `E_磨合` | 第 1/2/3 季起：`0.5 / 0.75 / 1.0` | 0.50–1.00 |
| 研究加成 | 每块研究地块 +1%，上限 +3% | 1.00–1.03 |

> ⚠️ `E_幸福` **用上一季的 H**。第一季用 `H₀ = 0.6`。
> ⚠️ 升级中 / 在建 / 未运行的地块**不提供**邻接加成。

### 2.2 三量

```
产量     = e × u × E
商品投入 = input × u × E
劳动     = d × u          ← 【不乘 E】
经营费   = 0                , u = 0
         = 0.7c + 0.3c×u×E , u > 0
```

> **`劳动` 不乘 `E`** —— 效率高只是同样的人干更多批次。
> ⚠️ 注：此"劳动 = d × u"是**工资口径**（按本季实际开工发薪），**口径未变，不是岗位数 `L`**（2026-10-16 岗位口径变更时的拆分注记）。

### 2.3 人口与粮食

```
L = Σd                              岗位数（所有已建成地块，**不乘 u**；2026-10-16 岗位口径变更）
N = L × 2                           人口（r = 2）★ 不取整
ḡ = 已建成地块平均等级（含服务/研究）（2026-10-16 岗位口径变更：由「开工」改「已建成」）
m = 1 + 0.15 × (ḡ − 1)              等级乘数
F_基准 = (N/5) × m
F_优秀 = 1.5 × F_基准
```

> ⚠️ **`N` 不取整（✅ 2026-10-16 定案，取消 `round`）**：`L` 与 `N` 都保留小数——
> `u` 是 0–1 的比例、`d` 本身就有 `1.5 / 2.5`，所以 `L` 天然带小数。
> **引擎一律存小数**（否则账对不上），**取整是显示层的事**（界面上不出现"1.5 人"）。
> 原写法 `N = round(L × 2)` 作废。详见基线 §3.3.1。

### 2.4 幸福度 H（**结算时算**）

```
H = 0.6 × (F/F_基准)                            , F < F_基准
H = 0.6 + 0.4 × (F−F_基准)/(F_优秀−F_基准)      , F_基准 ≤ F < F_优秀
H = 1.0                                         , F ≥ F_优秀
```

> **零需求边界**：`F_基准 = 0`（一块地都没有）→ **H 保持上季值，首季取 H₀ = 0.6，不再返回 1.0**（2026-10-16 岗位口径变更）

### 2.5 粮食两档（**最易写错，请重点核对**）

**基准档：A、B 必须都有，且可互换**

```
R = 0.6 × F_基准
S = min(A投放, 0.4×F_基准) + min(B投放, 0.2×F_基准)

A投放 = 0 或 B投放 = 0  →  基准档不成立
S ≥ R  →  基准达标
```

**优秀档：A、B、C、D 四样全要**

配比 `A 0.4 / B 0.2 / C 0.1 / D 0.02`

**扣减：有多少扣多少，不足扣光，不欠账。**

> ⚠️ **粮食在结算时扣，不在期初。** 买不买粮是玩家的主动决策。

> ⚠️ **产出不能吃（✅ 2026-10-16）**：`A投放 / B投放` 里**只算本季【买来的】口粮**——
> 产出的 A/B/C/D 已经全部是市场供给，**不在可吃清单里**（见 §2.6）。
> **只种地、不买口粮 → H = 0**；买多了没吃完的部分 → **丢弃**（不产生收入、不结转）。

### 2.6 市场定价

```
s = Es × Q0 / P0
d = |Ed| × Q0 / P0
P_t = P0 + (B_t − X_t) / (s + d)
P_t = max(P_t, 0.1 × P0)
```

**买入按【上季结算价】、卖出按【本季价】——但两步都在【结算时】发生（✅ 2026-10-16 重定）。**

```
                  ★ X_t = 本季产出（− 合同交付量）
                     ——没有仓库：产出即供给，不申报卖出
季初无货 → 玩家申报需求（生产原料 + 建设物资 + 居民口粮）
              ↓
B_t = 生产原料 + 建设物资 + 居民口粮        ← 三段全计入，缺一不可
              ↓
P_t = P0 + (B_t − X_t)/(s + d)             ← 买入量顶高本季价
              ↓
卖出按 P_t；买入按【上季价】                ← 两者价差 = 交割成本
```

> ⚠️ **`X_t` 就是本季产出，没有任何需要推算的余地（✅ 2026-10-16）**。
> 用户原话：**"玩家不需要申报要卖，因为没有仓库，生产出来的就是'供'本身。"**
> 所以 `Plan` 里**没有 `sales` 字段**，流水线上也**没有"季末清仓"这一步**（基线 §11.1 整节作废）。
>
> | 由此定死的事 | 说明 |
> |---|---|
> | **不需要"申报卖出"** | 产出自动全部成为市场供给 |
> | **没有"季末清仓"** | 没有仓库就没有库存可清 |
> | **产出不能拿来吃** | 它已全部是市场供给；居民口粮只能从 `purchases` 买（§2.5） |
> | **唯一例外是合同** | 玩家间协议、低于市场价，见下 |
>
> **合同通道（✅ 已实现）**：产出 100% 自动进公开市场后，
> "我想把货便宜卖给隔壁老王"没有地方表达——**合同是唯一的例外通道**。
> 对求价的影响是**两侧都要扣**：
>
> ```
> 卖方：X_t = 本季产出 − 合同交付量      ← 货没进公开市场，不该压价
> 买方：B_t = 采购量   − 合同收货量      ← 货不是从公开市场买的，不该抬价
> ```
>
> 合同价由**双方协商、低于市场价**，不走 `P_t`。
> 落点：`Plan.contracts` + `pipeline._settle_contracts()`；
> **机制要点**：双方各自提交、字段完全一致才成立；收货用不完当季丢弃；交付不足的差额记 `shortfall`，不赔偿。

> ⚠️ **玩家阶段（期初）不动账户**：只提交 Plan，**不扣钱、不锁价**；采购的**记账与付款都在结算时**
> （与工资、经营费一起，见 §三 第 7 步"一次性扣款"）。
> 严格说这叫"**结算时按上季价买入**"——落点在**用哪个价**，不在**时点**；"期初按上期价买"只是口语说法。
> ⚠️ **首季没有"上季价"** → 用参考价 `P0` 兜底。
> ⚠️ **建设物资也计入 `B_t`**：买机械建厂同样会把机械价格顶高。
> ⚠️ **生产原料不进库存**：生产时当场消耗（否则会被居民当口粮吃掉——这是本轮抓到的一个真实 bug）。

价格触底时**按可实现需求量分配成交，不保证全量收购**；未售商品清理。

### 2.7 税收 / GDP

```
工资税 = W × 10%
增加值 = 有效产出价值 − 实际消耗的中间投入价值
```
GDP 用**固定统计价 P0**，不随季度成交价变。

## 三、季度执行顺序（程序的"心脏"）

> **2026-10-16 重排**：原第 4 步"**期初**：按上期价采购原料 + 扣工资经营费"**整条删除**。
> 现按用户裁定改为——**玩家阶段只提交 Plan，不扣钱、不锁价、不动账户**；
> 新增"**买入汇总与求价**"一步，物资款 + 工资 + 经营费并入"**一次性扣款**"。

```
1. 期初更新与公告（推进工期、到期完工本季可用；公布上期财报/价格/政策）
2. 玩家提交 Plan（哪块地开工、买什么、建什么、合同动作）
      ★ 只校验，不执行 —— 不扣钱、不锁价、不动账户
      ★ 也没有"申报卖出"：产出即供给（X_t = 本季产出）
3. 算效率 E（服务走独立分支：按自身等级 5% / 7.5% / 10%）
4. 算人口 L → N → ḡ → m → F_基准/F_优秀（供结算判定用）
5. 生产：产量 = e·u·E；算清本季的商品投入需求（★ 原料当场消耗，不进库存）
6. 买入汇总与求价：X_t = 本季产出（− 合同交付量）
      B_t = 生产原料 + 建设物资 + 居民口粮（三段）
      P_t = P0 + (B_t − X_t)/(s + d)      ← 买入量顶高本季价
      （粮食可选，玩家自己决定买不买）
7. ★ 一次性扣款：物资款（按【上季价】）+ 工资 + 经营费
      → 一笔从公用账户扣清        ← 本季【唯一】扣款点
8. 建设/升级推进工期（产出 / 路线建造时选定，建后不可更换）
9. 市场结算：全国求价，本季产出按【本季价 P_t】卖出（服务无收入，只有支出）
10.【粮食结算】扣【买来的】A/B/C/D → 得 H；多余的口粮丢弃
11. 工资税 + GDP + 报告
12. 结转（保存 H；没有库存字段可写——产出从不落地存放）
```

> ⚠️ **第 5 步"本季刚生产出的东西不能倒填本季已开始的消费"**。
> ⚠️ **第 10 步必须在第 9 步之后**（先卖出、再扣粮）。
> ⚠️ **资金校验放在第 7 步**：`物资款 + 工资 + 经营费 ≤ 现金`，超支即 Plan 无效。
> ⚠️ **本轮删掉的一步（✅ 2026-10-16）**：原第 11 步"**季末清仓**：出售全部尚未消耗的普通库存，清仓后归零"
> **整步删除**——没有仓库就没有库存可清（基线 §11.1 整节作废）。
> 连带口径：**产出不能吃**（第 10 步扣的只能是买来的口粮）、**买多了的口粮丢弃**（无收入、不结转）。
> ⚠️ **合同是唯一例外通道**：`Plan.contracts` 保留，**第一期提交即报错**（不静默忽略）。
> 详见基线 §6。
