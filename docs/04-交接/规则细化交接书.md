# 规则细化交接书

> **给规则细化的同学**
> 你的任务：把这份文档里的规则，细化成**程序可以直接读的 `config.json`**，并把每条规则的边界情况想清楚。
>
> 现状：**规则逻辑已经定完**，缺的是**数据落地**和**边界确认**。
> 你不需要设计玩法，只需要把下面这些"变成程序能吃的形状"。

## 〇、先看这三件事

### 1. 你的交付物是什么

| 交付物 | 内容 | 优先级 |
|---|---|---|
| **`config.json`** | 全部静态数据（配方/价格/工资/建设/政策） | 🔴 最高 |
| **边界情况清单** | 每条规则的"如果……怎么办" | 🔴 高 |
| **数值校验** | 关键数字的独立复算 | 🟡 中 |

### 2. 铁律：程序决定事实，AI 只负责解释

- **程序**算：产量、成本、价格、结算、税收、处罚
- **AI** 只负责：财报解读、新闻、合同起草、政策说明
- **AI 不得**改规则、造补贴、改价格、定处罚

你写 config 时，**凡是"数值"都进 config；凡是"公式"都进代码**。不要试图用 config 表达 if-else 逻辑。

### 3. 已拍板的规则不要重新设计

下面标 ✅ 的**已经定了**，你只需要落地。标 ⚠️ 的**需要你或用户确认**。

### 1.4 邻接关联表（✅ 已拍板：不只看同类型）

**这是本轮改动最大的地方**——旧规则只算同类型，现在按关联表。

```json
"adjacency_table": {
  "agriculture": ["agriculture", "resource"],
  "resource":    ["resource", "industry"],
  "industry":    ["industry", "resource"],
  "service":     ["service", "agriculture", "industry"],
  "research":    ["industry", "high_tech"]
}
```

**规则**：每个关联邻居 → `+5%`，上限 `+40%`。

```
E_邻接 = 1 + min(0.05 × 关联邻居数, 0.40)
```

> ⚠️ **服务是唯一例外**：**任何**邻居都算，每个 `+10%`，不看关联表。
> 代码里服务要单独分支。**上限待定，见 §五。**

## 二、规则逻辑清单（已定，供你核对边界）

### 2.1 效率 E

```
E = E_邻接 × E_幸福 × E_磨合 × (1 + 研究加成)
```

**乘法，不是加法。**

| 分量 | 公式 | 范围 |
|---|---|---|
| `E_邻接` | `1 + min(0.05 × 关联邻居数, 0.40)` | 1.00–1.40 |
| `E_幸福` | `H < 0.6 → 0.90`；否则 `0.90 + (H−0.6)×0.5` | 0.90–1.10 |
| `E_磨合` | 第 1/2/3 季起：`0.5 / 0.75 / 1.0` | 0.50–1.00 |
| 研究加成 | 每块研究地块 +1%，上限 +3% | 1.00–1.03 |

> ⚠️ `E_幸福` **用上一季的 H**。第一季用 `H₀ = 0.6`。
> ⚠️ 升级中 / 在建 / 未运行的地块**不提供**邻接加成。

### 2.2 三量

```
产量     = e × u × E
商品投入 = input × u × E
劳动     = d × u          ← 【不乘 E】
经营费   = 0                , u = 0
         = 0.7c + 0.3c×u×E , u > 0
```

> **`劳动` 不乘 `E`** —— 效率高只是同样的人干更多批次。

### 2.3 人口与粮食

```
L = Σ(d × u)                        岗位数
N = round(L × 2)                    人口
ḡ = 开工地块平均等级（含服务/研究）
m = 1 + 0.15 × (ḡ − 1)              等级乘数
F_基准 = (N/5) × m
F_优秀 = 1.5 × F_基准
```

### 2.4 幸福度 H（**结算时算**）

```
H = 0.6 × (F/F_基准)                            , F < F_基准
H = 0.6 + 0.4 × (F−F_基准)/(F_优秀−F_基准)      , F_基准 ≤ F < F_优秀
H = 1.0                                         , F ≥ F_优秀
```

### 2.5 粮食两档（**最易写错，请重点核对**）

**基准档：A、B 必须都有，且可互换**

```
R = 0.6 × F_基准
S = min(A投放, 0.4×F_基准) + min(B投放, 0.2×F_基准)

A投放 = 0 或 B投放 = 0  →  基准档不成立
S ≥ R  →  基准达标
```

**优秀档：A、B、C、D 四样全要**

配比 `A 0.4 / B 0.2 / C 0.1 / D 0.02`

**扣减：有多少扣多少，不足扣光，不欠账。**

> ⚠️ **粮食在结算时扣，不在期初。** 买不买粮是玩家的主动决策。

### 2.6 市场定价

```
s = Es × Q0 / P0
d = |Ed| × Q0 / P0
P_t = P0 + (B_t − X_t) / (s + d)
P_t = max(P_t, 0.1 × P0)
```

**期初按上期价买，季末按本期价卖。**
价格触底时**按可实现需求量分配成交，不保证全量收购**；未售商品清理。

### 2.7 税收 / GDP

```
工资税 = W × 10%
增加值 = 有效产出价值 − 实际消耗的中间投入价值
```
GDP 用**固定统计价 P0**，不随季度成交价变。

## 三、季度执行顺序（程序的"心脏"）

```
1. 玩家提交 Plan（哪块地开工、买什么、建什么）
2. 算效率 E（服务走独立分支）
3. 算人口 L → N → ḡ → m → F_基准/F_优秀
4. 期初：按上期价采购原料 + 扣工资经营费
      （粮食可选，玩家自己决定买不买）
5. 生产：产量 = e·u·E，成本 = 原料+经营费+工资
6. 建设/升级推进工期
7. 市场结算：全国求价 + 服务（服务无收入，只有支出）
8. 【粮食结算】扣 A/B/C/D → 得 H
9. 工资税 + GDP + 报告
10. 结转（保存 H，不保存普通库存）
```

> ⚠️ **第 4 步"本季刚生产出的东西不能倒填本季已开始的消费"**。
> ⚠️ **第 8 步必须在第 7 步之后**。
