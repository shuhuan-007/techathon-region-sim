# 演示操作稿（黑客松 · region-sim）

> 本稿按用户定的「演示五步」写成，每一步给三栏：**说什么（一句话）／屏幕上应该看到什么（实测数字）／注意什么**。
> 全部数字来自 **2026-10-17 用 HTTP 真跑一局（game=demo2）** 的实测，不是估算。
> 跑法前提：起服务器带两个环境变量 `NARRATE_OFFLINE=0`、`AI_TIMEOUT=300`。

## 实测环境速览（先背下来）

- **开局固定**：现金 **1200.0**、第 **1/20** 季、**零地块**、10×10 全可建空地。
- **建设计费**（农业 A，1 级，实测 from 结算 facts）：
  - 现金费：原价 80，**开局每类前 3 块半价 = 40**，第 4 块起恢复 80。
  - 材料费：每块 H-A×1，单价 **64.00**（材料**不打折**）。
  - 单块实付 = 40 现金 + 64 材料 = **104**（前 3 块）／80+64=**144**（第 4 块）。
- **结算顺序铁律**：`submit` 只记忆不扣款 → `end_quarter` 一次性扣款 → `next_quarter` 推进。
- **叙事时机**：**只有 `GET /api/state` 会生成两路叙事（新闻 + 财报），按季缓存**；`end_quarter`/`next_quarter` 秒回不等模型。

---

## 第 ① 步　开局

- **说什么**：新开一局，白手起家——1200 现金、一块地都没有。
- **屏幕上应该看到什么**：
  - 现金 **1200.0**，季度 **1 / 20**，地块数 **0**。
  - `POST /api/new_game` 实测 **耗时 0.02s**（HTTP 200）。
- **注意什么**：这步是纯本地，秒回，不用等。开场白就在这步讲完。

## 第 ② 步　建 4 块农业地（重点秀减免）

- **说什么**：连建 4 块农业 A（@0,0、1,0、2,0、3,0）——前 3 块吃到半价，第 4 块全价，让观众看到"减免有上限"。
- **屏幕上应该看到什么**：
  - 提交后 `can_settle = true`，`settle_blockers = []`（可以结算）。
  - **关键点**：提交瞬间现金仍显示 **1200.0、地块 0**——提交不扣款（实测 from `submit` 响应）。
  - `POST /api/submit` 实测 **耗时 <0.01s**。
- **注意什么**：
  - 别在这步说"扣了多少钱"——**钱还没扣**，扣款看第 ③ 步结算。
  - 建造时必须选定产出 `product="A"`（建后不可换，用户裁定）。

## 第 ③ 步　提交计划 → 结算 → 看月报

- **说什么**：点结算，一次性扣款，看这季的月报。
- **屏幕上应该看到什么**：
  - 结算后现金 **744.0**（1200 − **456**），进入第 **2** 季，地块数 **4**。
  - 456 的拆分（实测）：现金减免后 **40×3 + 80×1 = 200** + 材料 **64×4 = 256** = **456**。
  - `end_quarter` 实测 **0.02s 秒回**（不等模型）；`next_quarter` **0.03s**。
  - **看月报那一下**：`GET /api/state` 首次触发生成两路叙事，**实测耗时 134–181s**（两路真跑模型），`news_ok=true`、`report_ok=true`。
- **注意什么**：
  - **这是演示最怕卡的一步**——134–181 秒的等待必须提前想好串词（比如切去讲架构图），别让现场干等。
  - 同季内读第二次 `state` 走缓存、秒回；所以**彩排时把叙事先跑出缓存**，正式演示直接用缓存。
  - 财报那一路 `ok` 现在稳定为 **true**（本次修复验证）。

## 第 ④ 步　存档 → 读档

- **说什么**：存档落盘，重启服务，读回来——数字一字不差。
- **屏幕上应该看到什么**：
  - 存档文件 `saves/demo2.json` 在结算后**已存在**。
  - 读档前：现金 **744.0**、第 **2** 季、地块 **4**。
  - 重启后 `GET /api/state`（新 registry 从磁盘读）：现金 **744.0**、第 **2** 季、地块 **4**，**三项与读档前完全一致（match=true）**，且**上季 report 仍在**。
  - 读档 `state` 实测 **57.43s**（仍含叙事；若已缓存则秒回）。
- **注意什么**：
  - 演示"重启"就是 kill 掉服务进程再起；**确认 8211 端口先释放再重启**（实测约 2s 释放）。
  - 别漏了"report 仍在"这个点——它是本轮刚修过的回归点。

## 第 ⑤ 步　AI 上场（压轴）

- **说什么**：局面丢给 AI，让它给建议——注意它**只建议、不能替你提交**。
- **调用**：`POST /api/ai/advise`，带 `question`（可不带 `preview_plan`）。
- **屏幕上应该看到什么（实测原话，kimi-k3，耗时 40.62s，ok=true）**：

  > 能引用的数字只有局面上这些：现金 744、第 2/20 季、幸福度 0.6、collecting 阶段（本季还能行动、尚不能结算）；人口是 null，拿不到。我手里的规则摘要只有 §11.4，**没有地块建造成本和农业 A 的产出参数**，所以「再建几块、花多少、回本多少」我给不出数——给了就是编的。
  >
  > 可执行建议：先调 get_rules 查经济参数，或直接丢给我一个候选计划（例如「在 (4,0)、(5,0) 再建 2 块农业 A」），我用确定性计算器试算合法性与现金是否够用，结果交你定夺——提交永远由你走 /api/submit。

  - 证据区（evidence）逐项摆出引用的数字：cash=744.0、quarter=2、happiness=0.6、population=null。
- **注意什么**：
  - 这段最能打的点是 **AI 诚实**：它不认识的参数明说"给了就是编的"，并把提交权交还玩家（`next_step` 原话：*玩家确认后由前端走 /api/submit 提交（AI 无 commit）*）。
  - 想让 AI 给出**带数字**的建议，就带 `preview_plan` 让它试算；但那会再烧一次模型调用（本稿为控配额未演示）。
  - AI 这步 40s 量级，同样要备好串词。

## 全程耗时一览（实测，演示排练用）

| 步骤 | 端点 | 实测耗时 | 是否等模型 |
|---|---|---|---|
| ① 开局 | `new_game` | 0.02s | 否 |
| ② 建造 | `submit` | <0.01s | 否 |
| ③a 结算 | `end_quarter` | 0.02s | 否 |
| ③b 推进 | `next_quarter` | 0.03s | 否 |
| ③c 看月报 | `state`（首次） | **134–181s** | **是（两路叙事）** |
| ④ 读档 | `state`（重启后） | 57.43s | 是（若未缓存） |
| ⑤ AI | `ai/advise` | 40.62s | 是 |

**给演示者的提醒**：③c 和 ⑤ 是仅有的两处"会等模型"——**彩排先把叙事跑出缓存**，正式演示即秒回；AI 那段另备 40s 串词。
