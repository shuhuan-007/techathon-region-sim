# 前端设计规范（草案 v0.3）

> ## ⚠️ 首要原则（用户拍板）
>
> **前端布局一切以实际程序为准，随时调整。** 前端同学的原型（`index(1).html`）**只是参考**，
> 不是规格书——**程序跑出什么，界面就画什么**，冲突时以程序为准，界面跟着程序改。
>
> 所以本文件里的**配色、布局、图元**都可以改；**只有"规则语义"那部分是硬约束**（见各节 ⚠️ 标注）。

> **2026-10-18 第九轮同步（最新）**：**邻接加成不封顶**——`adjacency_cap` / `service_cap` 双双为 `null`；
> 服务**只给出去、自己不接收**，率按自身等级 **5% / 7.5% / 10%**；服务**有收入** 每邻 **12 / 20 / 28**。
> 「封顶 +40%」及第八轮的 8% / 12% / 16% **均已作废**（见 §3.2.1）。
>
> **2026-10-16 同步**：①服务邻接加成改为**按服务自身等级 5% / 7.5% / 10%**（见 §3.2.1）
> ②`N = L × 2` **取消取整**——引擎存小数，界面负责取整（见 §2.1）
> ③采购一律改为**结算时一次性扣款**——玩家阶段只提交 Plan，界面里不出现"期初扣款"字样（见 §2.3）
> ④H*/I 的固定收购**已全部停用**，所有商品只走供需曲线
> ⑤建造时必须**选定产出 / 路线**，建后不可更换（见 §6.2-12）
>
> **v0.3 更新**：①**开局减免 = 每类型独立名额**（机制已换，见 §3.1.1-②）
> ②**邻接口径纠错**：`E_邻接` 只认关联表，**农业旁边的工业不加成**（见 §3.1.1-①、§3.2.1）
> ③新增「选中地块高亮关联邻居」界面建议（见 §3.2.1）
>
> **v0.2 更新（用户拍板）**：①按钮改名 ②**每种地块×每级都要独立美术** ③**地图 10×10 + 可缩放**

### 2.3 新增：`推进本季度` ★

**你要求的：右上角，需要"有可执行的完整方案"后才能点。**

```
┌──────────────────────┐
│   ▶ 推进本季度        │   ← 可点（计划完整）
└──────────────────────┘

┌──────────────────────┐
│   ▶ 推进本季度  ⚠     │   ← 灰置 + 提示
└──────────────────────┘
   还有 2 块地未安排
```

**可点条件（建议）**：

| 条件 | 检查 |
|---|---|
| 每块地都已安排 | 运行 / 在建 / 停工 / 空地（有明确状态） |
| 现金不为负 | `cash ≥ 0` |
| 无待处理冲突 | 如买了不存在的商品 |

**校验由后端做**（守"程序决定事实"），前端只显示结果：

```
GET /state → { ..., "can_settle": false, "settle_blockers": ["还有 2 块地未安排"] }
```

> **注意**：这里和《项目架构-总》（docs/03-架构/项目架构-总.md）§三"回合循环与状态机"里"提交计划 / 结束季度"两步对应。
> 若合并为一步，`推进本季度` = 提交；若分两步，它还负责触发结算。

> ⚠️ **钱只在结算时动一次**（✅ 2026-10-16 定案）：玩家阶段**只提交 Plan**——**不扣钱、不锁价、账户原封不动**。
> 所以顶栏的**现金在点 `推进本季度` 之前不会变**；物资款（按**上季价**记账）+ 工资 + 经营费在结算时
> **一笔扣清**（基线 §6 第 5 步"一次性扣款"）。
> 界面上**不要出现"期初采购 / 期初扣款"这类进度提示**——本季唯一扣款点就是结算。

## 三、地块区

### 3.1 地图：10×10 + 可缩放 ⚠️（**已拍板**）

**10×10 = 100 格**，支持缩放（滚轮/按钮）。

> ⚠️ **注意：这不是"地图变大"这么简单，它改变了邻接加成的性质。** 见 §3.1.1。

**实现要点**：

| 项 | 做法 |
|---|---|
| 地块 ID | **坐标制** `"x3_y5"`（不用数组下标） |
| 缩放 | CSS `transform: scale()` + 容器滚动；或调整格子基准尺寸 |
| 拖拽平移 | 建议加（10×10 一屏放不下） |
| 性能 | 100 格不重，**第一期不用做虚拟化** |

#### 3.1.1 10×10 带来的两个规则影响 ★

**① 邻接加成：10×10 只是让"够得着上限的位置"变多，不是让加成变容易**

> ⚠️ **先纠正一个易错点**：`E_邻接` 数的是**关联邻居**，不是"邻居总数"。
>
> ```
> E_邻接 = 1 + 0.05 × N_关联 + Σ相邻服务的加成（不封顶）
> ```
> `N_关联` = 邻居中**类型落在关联表里**的那些。
> **农业旁边的工业不算数**（关联表：`农业 → [农业, 资源]`）。
> 所以一块农业四周全是工业 → `N_关联 = 0` → `E_邻接 = 1.00`。

**每块地能拿到多少，取决于两件事**：① 它有**几个邻居位**（网格几何）② 这些邻居**是不是关联类型**（玩家布置）。

**10×10 只改变 ①，且只改变"多少块地拥有 8 个邻居位"**：

| 网格 | 有 8 邻居位的地块 | 每块地可达加成（几何极值） |
|---|---:|---|
| 3×4 | 2 格（16%） | 角格 +15% / 边格 +25% / 内圈 +40% |
| **10×10** | **64 格（64%）** | 同上（**邻居位数量没变**） |

> **关键**：**每块地的邻居位一样多**（最多 8 个）。
> **2026-10-18 第九轮**：加成**已不封顶**，所以这里的 `+40%` 是**"8 个邻居位 × 每邻 5%"的几何极值，不是规则封顶**——
> 一圈全是三级服务时可达 **+80%**（`E = 1.80`）。10×10 改变的只是**"有 8 个邻居位的地块"从 2 块变成 64 块**。
>
> **而且冲满 8 个邻居位依然很难**——需要围着它建 **8 块给它加成的地**。
> 关联表是**限制性**的（农业只认农业和资源），所以：
> **位置策略深度没有崩，只是"好位置"不再稀缺。**
>
> **这基本是好事**：玩家有更多空间做规划，不用挤在 2 个内圈格里。
> ~~**上限 40% 本身仍是有效约束**，不用急着改。~~
> → **2026-10-18 第九轮作废**：封顶已删除，上界由"邻居位数 × 每邻加成"自然决定。

**② 开局减免：机制已换，10×10 下不受影响** ✅

**新机制（已拍板）：每种类型各有自己的「减免名额」**，不是"按品种数给折扣率"。

```
每种地块一份独立名额：{ 农业: n_农, 资源: n_资, 工业: n_工, 服务: n_服 }
名额内的「新建一级」打折；名额用完恢复原价
```

> **为什么这个机制不怕 10×10**：因为它**不依赖"品种数"**，而是靠**名额有限**起约束作用——
> All In 一种会很快用完名额、后面全价；铺开建多种则每种都吃到名额。
> **地图多大都一样有效。**

**界面要显示的**（给前端）——以下是**版式示意，数字非定值**：

```
建设面板 · 开局期：
  农业  名额 〔?〕 · 已用 1   [下一块享折扣]
  工业  名额 〔?〕 · 已用 2   [名额已用完，按原价]
  服务  名额 〔?〕 · 已用 0   [下一块享折扣]
  资源  名额 〔?〕 · 已用 0
```

> ⚠️ **名额数与折扣幅度均未定**。用户给的 2/2/1 **只是举例**，且明确说**不要照抄**。
> **机制定了，数值没定**——先留位置，数值等拍板。

#### 3.2.1 关联表（**算 `E_邻接` 的唯一依据**）

| 地块类型 | 关联类型（各 +5%） |
|---|---|
| **农业** | 农业、资源 |
| **资源** | 资源、工业 |
| **工业** | 工业、资源 |
| **服务** | ——（**不在表里**：服务只给出去，自己不接收任何加成，见下） |
| **研究** | 工业、高技术 |

```
E_邻接 = 1 + 0.05 × 关联邻居数 + Σ相邻服务的加成（不封顶）
```

> ⚠️ **农业旁边的工业不算加成** —— 关联表里没有。
> **这是玩家最容易误解的地方，界面务必在悬停/图例里说清**：
>
> ```
> 农业地块 · 邻接 +5%（1 个关联邻居：旁边那块农业）
>          ✗ 右边那块工业不加成
> ```
>
> **建议**：选中一块地时，**高亮所有给它加成的邻居**（关联的亮绿、不关联的暗灰）。
> 这比文字解释有效得多。

> ⚠️ **服务是唯一例外**：**只给出去、自己不接收**（✅ 2026-10-18 第九轮）——
> 给**八邻格里所有运行中的非服务地块**加成，率按**服务自身的等级**：一级 **+5%**、二级 **+7.5%**、三级 **+10%**；
> **服务自己不吃任何邻接加成**（`E_邻接` 恒 1.00）、**服务之间也不加成**，所以它不在上面那张关联表里。
> 加成**不封顶**（✅ 2026-10-18 第九轮；2026-10-16 晚的"封顶 +40%"作废）——8 块三级服务 = `+80%`。
> ~~而**别人给服务的加成**仍按关联表（服务认服务/农业/工业，每个 +5%、封顶 +40%）。~~
> → **2026-10-18 第九轮作废**：服务不接收任何加成。
>
> **改动说明（2026-10-16）**：此前是"任何邻居一律 +10%、不分等级"，导致三级服务与一级服务收益完全相同、升级无意义。
> 现按等级取率，界面上要能看出"这块服务是几级、给出多少"。详见基线 §3.6。
> **改动说明（2026-10-18 第九轮）**：封顶删除 + 率回调为 5%/7.5%/10%（第八轮的 8%/12%/16% 作废），
> 界面上不再出现「已封顶 / capped」字样，只显示"加成合计 +X%"。

## 五、AI 助手对话 ★（新增，他原型没有）

### 5.1 形态

**唤起式浮层**，不常驻（避免挡地图）。

```
                        ┌────────────────────────────────┐
                        │  AI 助手                    ✕  │
                        ├────────────────────────────────┤
                        │ 玩家：我想搞农业，但不太懂      │
                        │                                │
                        │ AI：你这季有 1200 现金。建议…   │
                        │      [试算结果] 建农业 L1       │
                        │      成本 80 + H-A×1           │
                        │      产出 A×5，按当前价 ¥10     │
                        │      ┌──────────┐              │
                        │      │ 采用此方案 │              │
                        │      └──────────┘              │
                        ├────────────────────────────────┤
                        │ [说大方向…]              [发送] │
                        └────────────────────────────────┘
```

### 5.2 玩家能做的两件事（**你要求的**）

| 方式 | 交互 |
|---|---|
| **直接操作地块** | 点地块 → 弹出操作菜单（开工比例/升级/拆除） |
| **说大方向让 AI 草拟** | 在对话框输入意图 → AI 生成 `Plan` 草稿 → **玩家确认** |

### 5.3 AI 能做的（**边界，务必守**）

| ✅ AI 能 | ❌ AI 不能 |
|---|---|
| 给建议、总结、解释 | **直接改状态** |
| **试算**（调 `preview`） | **提交**（没有 `tool_commit`） |
| **起草** `Plan` | 绕过 `validate` |
| 算"如果建了会怎样" | 自己心算数字（必须调引擎） |

> **关键**：AI 起草的 Plan **走和玩家手填完全相同的入口**（同一个 `validate`）。
> **"能算" ≠ "能改"。**

### 5.4 界面上要体现"数字来自引擎"

AI 回复里的数字，**要能看出是引擎算的**（而不是 AI 编的）：

```
AI：如果在这建服务（成本 80 + H-J×1）：
    · 给出邻接 3 块地各 +5%（新建一级服务）
    · 服务收入 每邻 12 × 3 块 = 36
    · 每季净支出 ¥34（c=10、工资 3×8=24）
    · 下季现金预计 ¥1,166     ← 标注"（引擎试算）"
```

> 注：上例按 **2026-10-18 第九轮**口径重算（服务 `c` 20→**10**、工资 16→**8**、收入 12/20/28）。
> 原示例的 `¥68 / ¥1,132` 是按旧 `c=20 / 工资 16` 算的，**已作废**。

> 建议加一个小标记，表明这是 `preview` 的结果。**玩家信任来自"数字可复现"。**
