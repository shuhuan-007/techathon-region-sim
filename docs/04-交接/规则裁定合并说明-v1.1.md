## 二、❌ 驳回四条（核心冲突，不再复议）

### 驳回 1-4 是**同一个死结**，必须整体看

队友同时主张「**没有仓库 → 季末清仓**」与「**固定价 → 清仓不影响价格**」。
在动态曲线下这不成立：

```
季末清仓 → X_t 推到极大 → P_t = P0 + (B_t − X_t)/(s+d) 被打到 P_min
```

**两条只能留一条。用户裁定：留动态曲线。**

### 因此以下队友条款整节驳回

| 队友原文位置 | 被驳回的主张 | 本项目口径（基线） |
|---|---|---|
| §4.1 | 买入价＝P0、卖出价＝P0、跨季不变、无价差、无手续费 | §4.1 动态曲线；买入按上季价、卖出按本季价 |
| §4.2 | 当前固定价模式不使用弹性计算价格变化 | 弹性**正在使用**，`P_t` 由 `Es/Ed` 算出 |
| §4.5 | 季末按 P0 全部出售、中央收购不限量、商品退出模拟 | 产出即供给；`P_min` 触底时**不保证全量成交**，未售清理不产生收入 |
| §5 | 普通可交易商品季末全部出售 | **没有库存可清**；未投入工程的材料随产出即进入市场 |
| §11 | "中央收购不限量""不存在 30/15/10 分支" | 前半驳回（不保证全量）；后半**早已停用**，方向一致 |

> ⚠️ **`sell_all_tradable_inventory_at_quarter_end`**：源 JSON 里为 `true`，
> **本项目已随"没有仓库"作废**（基线 §11.1 整节作废）。**不要再引用这一条。**

### 为什么必须保动态曲线（给队友的理由）

1. **M1 验收锚点全部由曲线算出**，改固定价则全部作废：
   甲 `P_t = 23.52`／乙 `55.222222`；期末现金 `1031.68`／`1065.611111`；增加值合计 **176**。
2. **弹性表是队友自己交的**，正是为曲线准备的；改固定价等于让这份数据白交。
3. **动态曲线是"玩家 vs 全国市场"模型，与人数无关**——
   第一期只做一个玩家，`B_t`/`X_t` 只是往曲线上加一笔，**完全算得动**。

## 三、✅ 采纳（6 条）

### 3.1 人口（第 5 条）—— 与基线一致，确认

```
L = Σ(d_i × u_i)          实际用工量（劳动投入当量）
N = 2 × L                 总人口
```

- 允许 `L` 为小数、允许 `N` 为小数；
- **不 `round`、不 `ceil`、不逐地块取整**；
- **劳动及人口不乘生产效率 `E`**；
- **工资按实际用工 `L` 计算**，不因 `N = 2L` 而自动翻倍；
- 示例：`d=3, u=0.75` → `L=2.25` → `N=4.5`；
- 每 5 人一份基础生活需求：`D = N/5`；
- **显示精度与计算精度分离**：界面可格式化显示，**不得用显示值覆盖内部计算值**。

> 与基线 §3.3.1 完全一致。**`r = 2` 已定案**。

### 3.2 开局现金 = 1200（第 8 条）

- 基线 T5 由 `未填(null)` → **`1200`**。
- ⚠️ **连带影响**：M1 锚点的期末现金是在"各 1000 现金"下算出的，
  **基线 §8.1 的 M1 题设仍按 1000**（那是测试题设，不是正式开局值）。
  正式开局 1200 与 M1 夹具 1000 **并存，不矛盾**——但**不得把 1200 当 M1 输入**。

### 3.3 总季数 = 20（第 9 条）

- 基线 T8 由 `40` → **`20`**。
- ⚠️ **连带影响**：基线 §5.2 高技术路线总工期 **14 季**，
  20 季局里"开局即投高技术"才勉强走完；基线原注"16–20 季偏短"**依然成立**。
  **这是已知的玩法取舍，用户已知情接受，不再复议。**

### 3.4 服务邻接封顶 40%（第 6 条）★ 填入基线待定项

| 项目 | 原基线 | **现裁定** |
|---|---|---|
| 服务邻接上限 | **暂不封顶**（三级+8邻居 理论 +80%） | **封顶 +40%** |
| 服务是否叠普通分支 | 否（已独立分支） | **否，确认不重复叠加** |

```
E_邻接(服务) = 1 + min( rate(服务等级) × (所有相邻地块数), 0.40 )
rate: 1级 = 0.05   2级 = 0.075   3级 = 0.10
```

> **这一条填的是基线自己标为"待定"的三处**（§3.6 注、§9-A3、§9-T3）。
> 原基线理由是"封顶只影响极端摆法，属初始估值"——**现按 40% 定死，与普通地块一致**。
>
> ⚠️ **注意取舍后果**：三级服务 + 8 邻居由 `+80%` 降到 `+40%`，
> **服务升级的边际收益因此变小**（1/2/3 级在 ≥8 邻居时都撞封顶）。
> 若实测发现"服务不值得升级"，回来调 `service_rate_by_level` 或本封顶值。

### 3.5 政策系统（第 11 条）★ 基线新增机制

**基线此前只有"政策八字段格式"，没有抽取与生效规则。现补齐：**

#### 抽取与生效

- 一局 **20 季**；**每一季开始**：上季政策到期 → 系统随机抽取本季政策 → **保存抽取结果** → 弹窗告知玩家 → 玩家看 AI 建议后制定计划；
- **第一季也抽取**；**每季恰好一项**；**四项各 25%**；**允许连续抽到相同政策**；
- **政策强制生效**，玩家**不能拒绝政策本身**（可拒绝 AI 建议）；
- **仅当季有效、不累计**；
- **重新打开界面或读取同一季度存档不重新抽取**。

#### 四项政策

| # | 政策 | 效果 |
|---|---|---|
| 1 | **常规环境** | 无额外修正 |
| 2 | **生产激励** | 商品生产地块效率 `×1.10`；工资 `×1.15` |
| 3 | **精益运营** | 商品生产地块效率 `×0.95`；经营费 `×0.90` |
| 4 | **民生优先** | **全部运行地块**工资 `×1.10` |

#### 作用范围

| 术语 | 定义 |
|---|---|
| **商品生产地块** | 使用**有可交易商品产出的生产配方**的地块。**不含**无商品产出的研究；**不含**本地服务 `J` |
| **全部运行地块** | 包含商品生产；包含**按原规则正常运行并支付工资**的服务和研究功能 |

> ⚠️ **停工且按原规则不发生工资的地块，不因政策凭空产生工资。**

#### 计算位置（重要，防误算）

```
E_base      = 原有效率公式的计算结果
E_effective = E_base × 政策效率乘数
```
- 生产产量和商品投入使用 `E_effective`；**劳动不乘 `E_effective`**；
- `wage_payment = 原工资计算结果 × 政策工资乘数`；
- `operating_cost = (原经营费公式用 E_effective 算出的结果) × 政策经营费乘数`。

**经营费减免不作用于**：另算的原料采购费、工资、建设现金费、建设材料费。

- **政策不改变邻接分项的 40% 上限**；
- **政策效率乘数在原有效率结果之后应用，不回写邻接参数**。

#### 两个平衡提示（写进文档防误读）

- **精益运营是取舍政策，不保证有利**：同开工量下产量下降；随效率计算的原料投入也下降；
  **工资不因效率下降而减少**；经营费得到额外减免。
- **民生优先增加工资支出**。若居民预算以实际工资为来源，应读取**政策调整后的实际工资**，
  但**不得因此另建一笔重复支出或重复收入**。

### 3.6 工程物资（第 12 条）

- **不存在"为未来工程合法预留普通库存"的机制**；
- **尚未投入工程的材料**：无论是否计划下季使用，**季末均出售**；
- **已正式投入工程的材料**：从普通库存扣除 → 记录在工程状态 → **不参与季末出售** → **不重复收取材料采购费**；
- **禁止同一份材料同时**：留在普通库存 / 被工程认定为已投入 / 又进入季末出售；
- 工程启动条件与材料数量**继续使用原建设表**。

> 示例：库存中 5 单位 `H-G`，计划下季升级 → **本季末出售**；
> 5 单位 `H-G` **已投入已启动工程** → **不出售**。
> 工程建成后生产出的其他商品，按正常商品规则处理，**可以出售**。

## 四、⏸ 暂不启用：采购上限（第 10 条）

| 项 | 值 |
|---|---|
| 基础商品 `A/B/C/D/F/G` | 每季 **10000** |
| 机械与高科技 `H-A/H-F/H-G/H-J/I/H-A+/H-F+/H-G+/H-J+` | 每季 **1000** |
| 状态 | **`enabled: false`（暂不启用，数值留存 config）** |

**口径（整套，启用时一并生效）**：季初重置；**未使用额度不累计**；**卖出不恢复额度**；
同一季度同一商品的中央采购**合并计数**（生产原料＋建设材料＋服务经营物资＋居民直接采购）；
**同一笔只统计一次**；**内部转交不重复统计**；**自产自用不占额度**；
校验 `已购量 + 本次采购量 <= 上限`。

> **为什么暂不启用**：已选**动态曲线**，买入会把价格推高，本身即是约束；
> 且数值**相对曲线规模无约束力**（`A` 的 `Q0 = 2000`，上限 `10000`，等于没有上限）。
>
> **同时明确三点**（防止被当成"机制已废"）：
> - 这是**玩家向中央购买的上限**，**不是中央向玩家收购的上限**；
> - 采购**必须支付现金**；**额度不是免费库存**；
> - **不得把季度采购上限当作动态市场 `Q0`**。
>
> 若后期要量化基线 §4.1"**禁止无限买入后立即转卖的投机指令**"，这套上限是现成手段。

|---|---|
| 邻居集合 | **八邻格**（不按几何距离临时推） |
| 判定方式 | **按关联表**（非同类型也算，见基线 §3.2） |

| 普通地块上限 | **+40%** |
| 服务（给出去） | 按服务自身等级 **5% / 7.5% / 10%**，**封顶 +40%**（见 §3.4） |
| 服务（收到） | 按关联表（服务认 服务/农业/工业），每邻居 +5%、封顶 +40% |

> ⚠️ **若日后要真正启用"关联度/等级权重"**，基线 §3.2 关联表与八邻格固定 5% **将不再成立**，

>
> **缺失时不得全部默认填 1，也不得擅自对称化**（关联表缺失应**报错**）。

## 八、撤销 / 停止事项（队友 §12 原文，确认有效）

玩家每季自行选择政策 · 精益运营改名为"降本限产" · 固定 `3×4`、12 块地 ·
