## 三、每一层做什么（边界）

### ① `web/` 前端

| 做 | 不做 |
|---|---|
| 显示地图、面板、月报 | ❌ **任何计算** |
| 把玩家操作打包成请求 | ❌ 算价格、算效率 |
| 高亮、悬停、动效 | ❌ 判断合法性 |

> **铁律**：前端**只显示后端给的数字**。效率值、粮食缺口都由后端算好。

### ② `server/` 服务层

| 做 | 不做 |
|---|---|
| 三状态机（收集/结算/月报） | ❌ **任何规则** |
| 校验 Plan（调 `engine.validate`） | ❌ 算价格、改状态 |
| 调 `engine.advance()` | ❌ 插值、取整 |
| 序列化返回 | |

> **铁律**：路由里**只做转发**。所有逻辑进 `engine/`。

### ③ `engine/` 引擎 ★

| 做 | 不做 |
|---|---|
| **全部业务逻辑** | ❌ import `server` |
| 纯函数、确定性 | ❌ 读写文件 |
| 可脱离 Web 单测 | ❌ 用 `random` / `datetime.now()` |

> **铁律**：引擎是**纯的**——输入状态+计划，输出新状态。没有副作用。

### ④ `ai/` AI 层

| 做 | 不做 |
|---|---|
| 把 `report` 数据变成人话 | ❌ **改规则** |
| 生成新闻、起草合同 | ❌ 造补贴、改价格 |
| 解释政策 | ❌ 定处罚 |

> **铁律**：**AI 只解释，不改事实。** `guard.py` 就是防这个的。
> **关键设计**：AI **不直接读 state**，只读 `engine/report.py` 生成的**结构化报告**——从源头限制它看得见什么。

### ⑤ `config/` 数据

| 做 | 不做 |
|---|---|
| 所有静态数值 | ❌ 任何 if-else 逻辑 |
| 可被非程序员编辑 | ❌ 藏公式 |

> **铁律**：**数值进 config，公式进代码。**

### ⑥ `storage/` 持久化

| 做 | 不做 |
|---|---|
| 存/取 `GameState` | ❌ 业务逻辑 |
| 版本迁移 | |

> **接口可替换**：第一期 JSON 文件，未来 Redis/Postgres 同接口。

## 七、两个"占位"模块，值得单独说

### 7.1 `engine/rng.py` —— 统一随机源

**为什么现在就要建**：防止有人在计算里直接 `import random`。

```python
# engine/rng.py
"""统一随机源。第一期恒返回固定值，保证确定性。"""

_SEED = 0

def rand() -> float:
    """第一期：恒返回 0.5，保证可重放。"""
    return 0.5

def randint(a: int, b: int) -> int:
    return a

# 未来如果要随机事件：
# def rand() -> float:
#     return _rng.random()      # _rng 由 seed 初始化，seed 存进存档
```

**价值**：**全局只有一个随机入口**。以后要加随机事件，改这一个文件；且 seed 存进存档，**重放必然一致**。

### 7.2 `engine/clock.py` —— 统一时间源

```python
# engine/clock.py
"""统一时间源。第一期不使用，仅为禁止直接调 datetime.now()。"""

def now():
    raise RuntimeError("引擎内不得使用真实时间，否则破坏确定性")
```

**价值**：**让违规显式报错**，而不是悄悄埋一个不确定性。

## 八、`report.py` 为什么重要

它是**引擎和 AI 之间的唯一接口**。

```python
@dataclass
class QuarterReport:
    quarter: int
    player_id: str
    income: dict[str, float]          # 各项收入
    expense: dict[str, float]         # 各项支出
    production: dict[str, float]      # 各商品产量
    food: FoodReport                  # 粮食结算详情
    happiness_before: float
    happiness_after: float
    gdp: float
    events: list[str]                 # 机械可读的事件列表
    warnings: list[str]               # 警告（缺料/触底/将破产）
```

**两个用途**：

| 用途 | 谁用 |
|---|---|
| 前端显示月报 | `web/` |
| **AI 写解读** | `ai/narrator.py` |

> **关键**：AI **不读 `GameState`，只读 `QuarterReport`**。
> 这样 AI 能看到的事实**是引擎筛过的**，从结构上防止它"看到全部数据后自己发挥"。

## 九、`ledger.py` 为什么重要

**记录"每一笔钱为什么变"**，用于调试。

```python
@dataclass
class LedgerEntry:
    quarter: int
    player_id: str
    kind: str        # "purchase" | "wage" | "sale" | "tax" | ...
    amount: float    # 正=收入，负=支出
    detail: str      # "买 C×2 @16.0"
```

**为什么现在就要**：

> M1 第一次跑**几乎肯定对不上 215 / 176**（★ 2026-10-16：锚点已从旧三数
> `1033.12 / 1049.65278 / 159` 改为不依赖价格弹性的生产总支出与增加值）。
> **（弹性已到位，结算价与期末现金也都可对，见《规则基线》§8.1 表 §六。）**
> 到那时你需要知道"**是产量算错了，还是原料算错了，还是税算错了**"。
> 有账本流水，就能一眼看出差在哪。

**建议**：`advance()` 里每一笔记账都 append 一条。**这是最划算的调试投资。**

## 十一、一句话总结

> **六个顶层目录**：`web` / `server` / `engine` / `ai` / `config` / `storage`
>
> **边界三句话**：
> - **engine 决定事实**（纯函数、确定性）
> - **ai 只解释事实**（只读 report，不读 state）
> - **web 只显示事实**（零计算）
>
> **两个占位模块现在就建**：`rng.py`、`clock.py`（防不确定性）
>
> **两个调试模块现在就建**：`ledger.py`（查账）、`report.py`（也是 AI 接口）
>
> **第一期留桩、不实现**：合同、政策、AI 真实调用、房间匹配
