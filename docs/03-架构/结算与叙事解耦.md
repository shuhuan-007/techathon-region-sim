# 结算提速 · 叙事与数字解耦（2026-10-18）

> 症状：点「▶ 推进本季度」后，数字迟迟不出来，像“结算要两分钟”；
> 顶栏还常出现「预览暂不可用」，看不出是钱不够还是服务端崩了。
>
> 结论：**引擎结算本身是 0 秒级**；慢的是 `/api/state` 里同步生成
> 新闻 + 财报解读（两路模型调用）。把叙事拆出去后，数字先出、叙事后台来。

---

## 一、检查到的事实

### 1. 结算本身

`POST /api/end_quarter` 只做「跑引擎 + 落存档」，实测 **0.0 秒级**（本机 MemoryStorage）；
它原本就已经用 `with_narratives=False`，不在结算里调模型。

### 2. 两分钟从哪来

`panel.js` 在结算后调 `GET /api/state`；旧 `state_for()` 默认 `with_narratives=True`，
`_narratives_for()` 会**同步**生成：

- `ai.narrate.narrate_news(...)` —— 一次模型调用
- `ai.narrate.narrate_report(...)` —— 再一次模型调用

两路串行，旧模型/网关下实测 134–181 秒；于是「拉状态」把整个界面卡住，
玩家感知成“结算要两分钟”。

### 3. 当前实测（qwen-flash，2026-10-18）

| 动作 | 耗时 |
|---|---:|
| `end_quarter`（引擎 + 落存档） | **0.0 s** |
| `/api/state`（只要数字，`narratives=0`） | **0.0 s** |
| `/api/narratives`（真调两路模型） | **8.34 s**（news 4.09 s + report 4.25 s） |

→ 即使模型慢到 2 分钟，**也不该挡住结算数字**；现在确实不挡了。

### 4. 「预览暂不可用」的真正原因

`POST /api/simulate` 跑的是真引擎副本；资金不足会抛 `SettlementError`。
旧 `_ERROR_MAP` 没有这个类型 → 500 `internal` → 前端 `runPreview` 只能显示
「预览暂不可用」。这是**业务结果**（钱不够），不是服务端故障。

## 二、改了什么

### 服务端

| 文件 | 改动 |
|---|---|
| `server/app.py` | `/api/state` 默认 `narratives=0`（只回数字）；新增 `GET /api/narratives`；`/api/simulate` **放行 `insufficient_cash_estimate` 粗估预警**（以真 preview 为准），捕获 `SettlementError` → 200 `{ok:true, report:null, blocker, kind:"settlement_failed"}`；`_ERROR_MAP` 把 `SettlementError` 翻成 400 `settlement_failed` |
| `server/session.py` | `state_for` 的 `with_narratives` 默认改 **False**；新增公开 `narratives_for()`（`/api/narratives` 入口，按季缓存、锁外、可能很慢） |
| `engine/pipeline.py` | `QuarterReport` 新增 `construction_events`（本季开工/完工事件）；`_advance_construction` / `_invest_construction` 返回事件，结算流水可显示“工程情况” |

### 前端

| 文件 | 改动 |
|---|---|
| `web/js/panel.js` | 结算后先拉 `/api/state?narratives=0` + `/api/map`，立刻渲染；`loadNarratives()` 在后台单独打 `/api/narratives`，新闻/财报面板显示“正在生成（不影响结算）”；`refresh()` 同样不 await 叙事；`/api/simulate` 失败时顶栏显示**第一条原因**（如“资金不足：需扣 472.21 / 有 416.00”），完整原因放 `title`；结算流水间隔 320ms → 140ms |
| `web/js/api.js` | 结算流水新增「工程开工/完工」逐条、「工程现金 + 物资」一行；成交行标注「本季终价」 |

## 三、现在的体验

1. 点「推进本季度」→ 提交 → 结算（0 秒级）→ 报告逐条弹出：
   - 每块地生产（开工率、产出商品×数量）；
   - 工程开工/完工（新增）；
   - 工程现金费 + 物资；
   - 卖出商品 × 数量 @ **本季终价**；
   - 材料/工资/经营/一次性扣款/税回流/销售收入/现金变化/GDP/幸福度/政策。
2. 数字渲染完成后加载框立即撤掉；**新闻/财报在后台生成**，
   面板显示“正在生成…（约 1–2 分钟；不影响结算，数字已经出来了）”。
3. 若某份草案超预算，顶栏不再写“预览暂不可用”，而是显示：
   `｜预览：现金可能不够：按参考价 P0 粗估，本季至少…`（完整原因悬停可见）。

## 四、验收

- `tests/test_server.py`：`/api/state` 默认不生成叙事、`?narratives=1` 显式生成；
  `/api/narratives` 独立路由形状 + 405。
- `tests/test_ai_endpoints.py`：`/api/simulate` 资金不足 → 200 + `blocker`，不是 500。
- `tests/test_construction.py`：1 季工程报告同时有 `started` 与 `completed` 事件。
- 全量 `region-sim/tests/` 21 个文件 `rc=0`。
- 真模型实测：`end_quarter` 0.0 s、`/api/state` 0.0 s、`/api/narratives` 8.34 s（qwen-flash）。

## 五、边界

- `/api/narratives` 仍然是一次**同步长请求**（两路模型）；只是不再挡住结算。
  若以后要“关闭页面也不中断”，需要改成后台线程 + 轮询；本期不做。
- 读档后 `raw_reports` 为空，新闻 facts 可能为 null（报告解读仍可生成）；
  这是既有 `news_facts` 依赖报告对象的问题，不在本次范围。
- 叙事失败只影响两个面板，不影响任何数字；失败原因会如实显示。
